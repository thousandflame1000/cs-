=== co-perf
**一句話**　程式跑多久 = 要做幾道指令 × 每道指令平均要幾拍 × 每一拍多長。

**想像一下**　搬家時間 = 箱子數 × 每箱要跑幾趟 × 每趟幾秒。只把其中一項變小，其他兩項可能跟著變大。

```fig
bars
bar 原本: 100 100 秒
bar 能加速的 80 秒變 4 倍快: 40 20 + 20 = 40 秒
bar 變無限快: 20 20 秒（剩下不能加速的）
cap: Amdahl：80% 能加速，再怎麼快也只剩 20 秒 → 最多快 5 倍
```

**動手算一次**　10 億道指令、每道平均 2 拍、時脈 2 GHz（一拍 0.5 奈秒）：$10^9\times2\times0.5\text{ns}=1$ 秒。

**Amdahl 定律**　能加速的部分佔 80%、加速 4 倍：新時間 $=0.2+0.8/4=0.4$，快 $1/0.4=2.5$ 倍。

**小心**
- MIPS（每秒幾百萬道指令）高不代表跑得快：不同 CPU 做同一件事的指令數不一樣。
- 好幾個程式的「快幾倍」要用幾何平均。
- 降時脈省的是功率；跑得比較久，總能量不一定省。

=== co-arith
**一句話**　二補數把負數想成「從 0 往回數」，這樣減法 = 加上負數，電腦只要一個加法器。

**想像一下**　4 位元就像只有 16 格的時鐘：從 0 往回撥 3 格是 13，所以 −3 就寫成 13（1101）。

```fig
array
row 5: 0 1 0 1
row −3: 1 1 0 1
row 相加: 0* 0* 1* 0*
cap: 0101 + 1101 = 1 0010，最前面多出來的 1 丟掉 → 0010 = 2
```

**動手算一次**　溢位只會發生在「兩個同號的數相加，結果卻變號」：$0111+0001=1000$，7+1 變成 −8。

**浮點數**　就是二進位的科學記號：正負號、指數、小數部分。$-6.25=-110.01_2=-1.1001\times2^2$ → 正負號 1、指數 $2+127=129$、小數部分 1001…

```fig
bits
top: −6.25 的 32 位元浮點數 = 0xC0C80000
bits: 正負號 1 1* | 指數 129 8 | 小數部分 1001000… 23
```

**小心**
- 浮點加法沒有結合律：大數加小數，小數可能整個被吃掉。
- 0.1 用二進位寫不完，所以 0.1+0.2 ≠ 0.3。

=== co-datapath
**一句話**　單週期 CPU：每道指令都給「最慢那道」的時間。多週期：把指令切成幾小步，簡單的指令少走幾步。

**想像一下**　洗衣店規定每位客人都佔用 2 小時，就算只是來拿衣服；改成按實際步驟計時，大家都快。

```fig
lanes
lw（載入）: 0 取指令 讀暫存器 ALU 讀記憶體 寫回
add（加法）: 0 取指令 讀暫存器 ALU 寫回
beq（分支）: 0 取指令 讀暫存器 ALU
cap: 多週期：lw 要 5 步、add 4 步、beq 3 步；單週期則每道都要等 lw 那麼久
```

**動手算一次**　取指令 200ps、讀暫存器 100、ALU 200、讀記憶體 200、寫回 100。lw 全部要走 = 800ps；add 不用碰記憶體 = 600ps。單週期的一拍必須是 800ps，add 也只好等 800。

**控制訊號**　每個選擇器（mux）都在問「這道指令的資料該走哪條路」：MemtoReg=1 表示寫回的是從記憶體讀到的（lw），=0 是 ALU 算出來的（add）。

**小心**
- 分支目標 = PC+4 + (位移量 × 4)，位移量是以「一道指令」為單位。

=== co-pipeline
**一句話**　管線就像洗衣、烘衣、摺衣三台機器同時給不同批衣服用：一批衣服沒有變快，但每小時完成的批數變多。

**想像一下**　第 1 批在烘的時候，第 2 批已經在洗了。

```fig
lanes
lw $1: 0 IF ID EX MEM WB
add 用 $1: 1 IF ID * EX* MEM WB
cap: add 需要 lw 讀到的值，但值在 MEM 結束才出現 → 只好插一個「泡泡」等一拍，再直接拿過來用（forwarding）
```

**動手算一次**　5 級管線跑 4 道指令，不用 $5\times4=20$ 拍，只要 $5+(4-1)=8$ 拍。

**三種卡住（危障）**
- 資料：要用的值還沒算好 → 把剛算出來的值直接拉過去（forwarding）；但 lw 後面馬上用，還是得等一拍。
- 控制：分支還沒決定要不要跳，就不知道下一道是誰 → 先猜，猜錯就丟掉。
- 結構：兩道指令同時要用同一個硬體。

**小心**
- 切越多級不一定越快：每級之間的暫存器也要時間，猜錯的代價也變大。

=== co-ilp
**一句話**　亂序執行：哪道指令的材料先到齊就先做，但最後一定照原本順序「交出去」，所以結果跟照順序做一樣。

**想像一下**　餐廳廚房：點單順序是 1、2、3 號，2 號的菜先備好就先炒；但出菜口還是照 1、2、3 的順序出。

```fig
flow
flow: 依序發出 -> 保留站：等材料 | 保留站：材料到了* -> 執行單元 -> 重排緩衝區 ROB -> 依序交出
cap: Tomasulo + ROB：中間可以亂序，頭尾一定照順序
```

**動手算一次**　除法 F0 = F2/F4 很慢；加法 F6 = F0+F8 要等 F0；減法 F8 = F10−F14 跟前面無關。減法可以先做。它會改 F8，但加法在「發出」時已經把舊的 F8 抄進保留站了，所以不會拿錯。

**改名字（暫存器重新命名）**　只有「讀到別人寫的值」（RAW）是真的要等。另外兩種只是名字撞到（像兩個人都把檔案取名 final.docx），換個名字就不衝突。

**小心**
- 一定要照順序交出，發生例外時才能停在正確的地方（精確例外）。
- 一次發好幾道指令不代表每拍真的能完成那麼多，會被相依性和分支限制。

=== co-cache
**一句話**　快取賭的是：剛用過的東西很快會再用；用了這個，旁邊的也會用。

**想像一下**　書桌（快取）和書櫃（記憶體）：常看的書放桌上；去書櫃拿書時，順便拿一整排。

```fig
bits
top: 32 位元位址，快取 16 KB、每塊 64 B、直接映射
bits: tag 18 | index 8* | offset 6
cap: offset：在這一塊的第幾個位元組。index：放在第幾格。tag：用來確認是不是要找的那一塊
```

**動手算一次**　每塊 64 B → offset $=\lg64=6$ 位；格子數 $=16\text{KB}/64\text{B}=256$ → index $=8$ 位；tag $=32-8-6=18$ 位。

**平均存取時間**　命中 1 拍、5% 沒命中、沒命中要 100 拍：$1+0.05\times100=6$ 拍。

**沒命中的三種原因**　第一次用（一定沒有）、放不下（快取太小）、撞位置（剛好要放同一格）。

**小心**
- 一格可以放好幾塊（提高關聯度），撞位置變少，但每次比對比較慢。
- 每塊越大不一定越好：塊數變少，沒命中時要搬更多。

=== co-vm-coherence
**一句話**　TLB 是「頁表的小抄」：最近用過的「虛擬頁 → 實體頁」對照記下來，不用每次都去翻頁表。

**一致性**　多核心各有自己的快取，同一個變數可能有好幾份。規定：要寫之前，先叫別人手上的那份作廢。

**想像一下**　全組各印了一份報告；有人要改，先大喊一聲「你們手上那份作廢」。

```fig
flow
flow: A 讀 x：A 獨有 E -> B 也讀：A、B 共享 S -> A 要寫：B 作廢 I，A 改過 M* -> B 再讀：A 交出新值，兩人 S
cap: MESI：Modified 改過、Exclusive 獨有、Shared 共享、Invalid 作廢
```

**動手算一次（VIPT）**　頁 4 KB、快取每路只能用頁內的 12 位元當 index+offset，所以每一路最多 4 KB；8 路 → 快取最大 32 KB，才不會有同一份資料放兩個地方的問題。

**小心**
- 快取一致性管的是「同一個位址」的值；記憶體一致性模型管的是「不同位址的寫入，別人看到的先後順序」。
