=== co-arith#1
title: 整數表示：無號、符號大小、一補數、二補數、溢位
mins: 35
goal: 會比較四種整數表示的範圍和零；會判斷有號、無號加法的溢位；會做符號延伸
---
> [!先記住]
> **二補數**：最高位代表 $-2^{n-1}$，其他位照常。8 位元可以表示 $-128$ 到 $127$。**取負號＝每個位元反過來，再加 1**。好處是加法和減法用同一個加法器。

```fig
array
row 權重: −128 64 32 16 8 4 2 1
row −6: 1* 1 1 1 1 0 1 0
cap: 最高位的權重是 −128，其他是正的。−128 + 64 + 32 + 16 + 8 + 2 = −6
```

同樣 4 個位元 `1011`，看你怎麼解讀：
- **無號**：$8+2+1=11$
- **符號大小**：最高位是正負號，其餘是大小：$-3$
- **一補數**：負數＝每一位反過來：`1011` 是 `0100`（4）反過來，所以 $-4$
- **二補數**：最高位權重 $-8$：$-8+2+1=-5$

?? 選擇 | 4 位元 `1001` 當作符號大小，是多少？
[ ] 9
[x] −1
[ ] −7
!! 最高位是負號，後面 `001` 是大小。
>> 符號 1 表示負，大小 1，所以 −1。（二補數會是 −7。）

| 表示法 | $n$ 位元範圍 | 幾個零 |
|---|---|---|
| 無號 | $0$ 到 $2^n-1$ | 1 |
| 符號大小 | $-(2^{n-1}-1)$ 到 $2^{n-1}-1$ | 2（+0、−0） |
| 一補數 | 同上 | 2 |
| 二補數 | $-2^{n-1}$ 到 $2^{n-1}-1$ | 1 |

二補數只有一個零，所以能多存一個負數。

?? 選擇 | 哪一種表示法有兩個零（+0 和 −0）？
[ ] 二補數
[x] 一補數
[ ] 無號
!! 一補數的 `0000` 反過來是什麼？
>> `1111` 也代表 0（−0）。符號大小也有兩個零。

**溢位**：答案超出能存的範圍。
- **無號加法**：最高位**有進位出來**就溢位。
- **有號（二補數）加法**：**兩個同號的數相加，結果卻變異號**就溢位。正＋負永遠不會溢位。

例（4 位元）：$5+4$：`0101`+`0100`=`1001`。兩個正數加出負數（−7），溢位！（9 超過 7。）

?? 選擇 | 4 位元二補數 $(-6)+(-3)$：`1010`+`1101`=`1 0111`。有溢位嗎？
[x] 有：兩個負數加出正數 `0111`
[ ] 沒有：最高位的進位丟掉就好
!! 丟掉進位後是 `0111`=7，兩個負數加起來會是正的嗎？
>> −9 超出 −8 的下限。判斷有號溢位看「同號相加變異號」，不是看有沒有進位出來。

等價的判斷法：**進入最高位的進位 ≠ 從最高位出去的進位**，就是有號溢位。

**符號延伸**：位數變多時，前面補**原本的最高位**（二補數）；無號數則補 0。

?? 選擇 | 把 8 位元二補數 `10010110` 延伸成 16 位元？
[x] `11111111 10010110`
[ ] `00000000 10010110`
[ ] `10000000 10010110`
!! 最高位是 1，前面補什麼？
>> 補 1，值不變（還是同一個負數）。

?? 填空 | 4 位元的「一補數」`1010` 是十進位多少？
== -5
!! 最高位是 1 是負數：把每一位反過來，看大小。
>> 反過來 `0101`=5，所以是 −5。

@例題 4 位元：算 $7+1$。分別當成無號和二補數，各有沒有溢位？
@寫 做二進位加法 | `0111` + `0001` = `1000`，最高位沒有進位出來。
@寫 當無號看 | 結果 8，範圍 0–15，沒有溢位（最高位沒有進位出去）。
@步 當二補數看 | 兩個正數加出 `1000` = −8，同號相加變異號：溢位。
@答 無號：沒溢位，答案 8；二補數：溢位（8 超過 7）。

=== co-arith#2
title: 加法器：ripple carry 和 carry lookahead
mins: 35
goal: 會用全加器串出 ripple carry 加法器、知道延遲是 $O(n)$；會寫 generate、propagate 和 lookahead 的進位式
---
> [!先記住]
> **漣波進位加法器**：每一位等前一位的進位，$n$ 位要等 $n$ 級，慢。**進位前瞻加法器（CLA）**：先算每一位「會不會自己產生進位」$g_i$ 和「會不會把進位傳下去」$p_i$，直接用公式算出所有進位，延遲變成 $O(\lg n)$。

```fig
flow: 漣波：c0 -> c1 -> c2 -> c3 -> c4!
flow: 前瞻：算出所有 g、p -> 同時得到 c1 c2 c3 c4*
cap: 漣波要一位一位等；前瞻一次算完（位數多時再分組、一層一層往上）
```

地基學過半加器（兩個位元相加）。**全加器**多吃一個「從右邊來的進位」$c_{in}$：
- 和 $s=a\oplus b\oplus c_{in}$
- 進位 $c_{out}=ab+(a\oplus b)c_{in}$（兩個以上是 1 就進位）

?? 填空 | 全加器 $a=1,b=1,c_{in}=1$，和 $s$ 是多少？
== 1
!! $1+1+1=3=11_2$。
>> 和 1、進位 1。

**Ripple carry 加法器**：把 $n$ 個全加器串起來，每一位的進位傳給下一位。

問題是**每一位都要等右邊算完進位**，進位像漣漪一樣一路傳過去，延遲跟 $n$ 成正比：$O(n)$。32 位元就要等 32 級。

?? 選擇 | 64 位元的 ripple carry 加法器，最慢的那條路經過幾個全加器？
[ ] 1
[ ] 6
[x] 64
!! 最高位要等誰？
>> 第 64 位的進位要等前面 63 位一個一個傳過來。

**Carry lookahead**：不要等，**直接算出每一位的進位**。定義兩個訊號：
- **generate** $g_i=a_ib_i$：這一位自己就會產生進位
- **propagate** $p_i=a_i+b_i$：右邊有進位來，這一位會把它傳下去

那麼 $c_{i+1}=g_i+p_ic_i$。把它一直展開：
$$c_2=g_1+p_1g_0+p_1p_0c_0$$
每個進位都只用 $a,b$ 和 $c_0$ 算，不用等。

?? 選擇 | $a_i=1$、$b_i=0$，這一位的 $g_i$、$p_i$ 是？
[x] $g_i=0$、$p_i=1$
[ ] $g_i=1$、$p_i=1$
[ ] $g_i=0$、$p_i=0$
!! $g=ab$、$p=a+b$。
>> 自己不會產生進位（$g=0$），但右邊有進位來時會傳下去（$p=1$）。

位數多時式子會太長，所以**分組**：4 位一組算出群組的 $G$、$P$，再對群組做一次 lookahead。延遲變成 $O(\lg n)$。

?? 選擇 | 為什麼 carry lookahead 比 ripple carry 快？
[x] 每一位的進位直接用輸入算出來，不必等前一位
[ ] 它用的閘比較少
[ ] 它只算一半的位元
!! ripple 慢在哪裡？
>> ripple 的進位要一級一級傳；lookahead 把傳遞的式子展開，平行算出來（代價是用比較多閘）。

@例題 4 位元 carry lookahead：$a=1011$、$b=0110$、$c_0=0$。算出每一位的 $g_i,p_i$ 和 $c_1,c_2$。（第 0 位是最右邊）
@寫 算 $g_i=a_ib_i$、$p_i=a_i+b_i$（$i=0..3$） | $a$：1,1,0,1（由右到左）；$b$：0,1,1,0。$g$：0,1,0,0；$p$：1,1,1,1。
@寫 算 $c_1=g_0+p_0c_0$ | $0+1\cdot0=0$
@步 算 $c_2=g_1+p_1g_0+p_1p_0c_0$ | $1+1\cdot0+1\cdot1\cdot0=1$
@答 $c_1=0$、$c_2=1$。（驗算：$1011+0110=10001$，第 1 位確實產生進位。）

=== co-arith#3
title: 乘法與除法：Booth 演算法
mins: 40
goal: 會手動跑 Booth 乘法（4 位元）；知道 radix-4 Booth 讓部分積減半；知道 C 的負數除法餘數跟被除數同號
---
> [!先記住]
> 乘法就是「移位再加」：乘數的每一位是 1，就把被乘數移到對應位置加上去。**Booth 演算法**把一串連續的 1 換成「一次減、一次加」，而且直接處理二補數的負數。

```fig
array
row 開始: 0000 1101 0
row 10：減 M、右移: 1111 0110 1
row 01：加 M、右移: 0000 1011 0
row 10：減 M、右移: 1111 0101 1
row 11：只右移: 1111 1010* 1
cap: 欄位是 A、Q、Q₋₁。結果 A Q = 1111 1010 = −6
```

二進位乘法最簡單的方法：跟小學直式一樣，乘數每一位是 1 就把被乘數**左移後加上去**。$n$ 位元要加 $n$ 次。

?? 填空 | 二進位 `101` × `11`（5 × 3）的結果是十進位多少？
== 15
!! `101` + `1010`。
>> 乘數最低位 1：加 `101`；第二位 1：加 `1010`。合計 `1111` = 15。

**Booth 演算法**：可以直接乘二補數（負數也行），而且遇到一長串 1 時加法比較少。

做法：$A$ 一開始是 0，$Q$ 是乘數，$q_{-1}=0$，$M$ 是被乘數。每一輪看 $Q$ 的最低位 $q_0$ 和 $q_{-1}$：
- `10`：$A\leftarrow A-M$
- `01`：$A\leftarrow A+M$
- `00`、`11`：不動

然後把 $(A,Q,q_{-1})$ 整個**算術右移**一位（最高位複製自己）。做 $n$ 輪，答案是 $AQ$。

?? 選擇 | Booth 演算法某一輪 $q_0=1$、$q_{-1}=0$，要做什麼？
[x] $A\leftarrow A-M$
[ ] $A\leftarrow A+M$
[ ] 不動
!! `10` 代表一串 1 的開頭。
>> 一串 1 開始時先減 $M$，結束時（`01`）再加回 $M$ 的高位倍數。

為什麼？一串 1 可以寫成「減一個、加一個」：$0111_2=1000_2-0001_2$。所以 Booth 在一串 1 的頭尾各做一次，中間只右移。

?? 選擇 | 乘數是 `0111 1110`，用 Booth 大約要做幾次加減？
[x] 2 次
[ ] 6 次
[ ] 8 次
!! 只有一串連續的 1：開頭減一次、結束加一次。
>> 直式乘法要加 6 次（6 個 1），Booth 只要 2 次。

**Radix-4 Booth**：一次看 3 個位元，每次處理 2 位，部分積的數量**減半**（乘以 $0,\pm1,\pm2$ 倍的 $M$）。

**除法**：restoring（減掉，變負就加回來）、non-restoring（變負先不加回，下一步改成加）。C 語言規定商往 0 截斷，**餘數跟被除數同號**：$-7/2=-3$，$-7\%2=-1$。

?? 填空 | C 語言裡 `-7 % 3` 是多少？
== -1
!! 商往 0 截斷：$-7/3=-2$，餘數 $=-7-(-2)(3)$。
>> $-7-(-6)=-1$，跟被除數 −7 同號。

@例題 用 Booth 算 $3\times(-2)$（4 位元）：$M=0011$，$Q=1110$。
@寫 第 1 輪：$(q_0,q_{-1})=(0,0)$，做什麼？右移後 $A,Q,q_{-1}$？ | 不動；右移：$A=0000$、$Q=0111$、$q_{-1}=0$。
@寫 第 2 輪：$(1,0)$ | $A=0000-0011=1101$；右移：$A=1110$、$Q=1011$、$q_{-1}=1$。
@寫 第 3、4 輪：都是 $(1,1)$ | 不動、右移兩次：$A=1111$、$Q=0101$，再 $A=1111$、$Q=1010$。
@答 $AQ=11111010=-6$ ✓

=== co-arith#4
title: IEEE 754 浮點數：符號、指數（偏移）、尾數
mins: 40
goal: 會把十進位小數轉成單精度浮點數、讀回來；知道指數全 0 和全 1 代表什麼；知道浮點數加法不滿足結合律
---
> [!先記住]
> 浮點數就是二進位的科學記號：**符號、指數、小數**。單精度 32 位元＝1 + 8 + 23，指數要減掉**偏移 127**；小數前面藏了一個看不見的 1。

```fig
bits: 符號 1* | 指數 8 | 小數 23
---
bits: 符號 1* | 指數 11 | 小數 52
cap: 上：單精度（偏移 127）；下：倍精度（偏移 1023）
```

科學記號 $-6.25=-1.5625\times10^0$。電腦用二進位的科學記號：
$$(-1)^s\times1.f\times2^{e-\text{bias}}$$

**單精度**（32 位元）：符號 1 位、指數 8 位、尾數（小數部分 $f$）23 位，bias $=127$。
倍精度（64 位元）：1、11、52，bias $=1023$。

先看影片：為什麼 0.1 + 0.2 不等於 0.3，再一步一步把 −6.25 存進去。

@影片 co-arith 0-78.1

?? 選擇 | 6.25 寫成二進位科學記號是？
[x] $1.1001\times2^2$
[ ] $1.25\times2^2$
[ ] $110.01\times2^0$
!! $6.25=110.01_2$，小數點往左移到只剩一個 1。
>> 左移 2 格：$1.1001\times2^2$。小數點前面不是 1 的寫法都沒有正規化。

步驟：
1. 轉成二進位：$6.25=110.01_2$
2. 正規化：$1.1001\times2^2$
3. 指數欄位存 $2+127=129=10000001$
4. 尾數只存小數點**後面**：$1001000\dots0$（前面的 1 不存，叫「隱藏位元」）
5. 符號：負數是 1

?? 填空 | 單精度浮點數，真正的指數是 $-3$，指數欄位存的是十進位多少？
== 124
!! 存 $e+127$。
>> $-3+127=124$。指數用**偏移**表示，不是二補數。

再看影片：0.1 為什麼存不準、格子的疏密，還有指數欄位的特別值。

@影片 co-arith 78.2-143.3

特殊值看指數欄位：

| 指數欄位 | 尾數 = 0 | 尾數 ≠ 0 |
|---|---|---|
| 全 0 | $\pm0$ | 次正規數（$0.f\times2^{-126}$） |
| 全 1 | $\pm\infty$ | NaN |

次正規數讓很小的數可以慢慢變成 0（逐漸下溢），代價是有效位數變少。

?? 選擇 | 指數欄位全是 1、尾數不是 0，代表？
[ ] 無限大
[x] NaN（不是一個數）
[ ] 最大的正規數
!! 尾數是 0 的話是 $\infty$。
>> NaN，例如 $0/0$。NaN 跟任何東西比都不相等，連自己也是。

最後一段影片：考試陷阱。

@影片 co-arith 143.4-173.1

浮點數的格子**離 0 越遠越稀**：每過一個 2 的次方，間距加倍。很多十進位小數（像 0.1）在二進位是無限循環，存不準。

**加法不滿足結合律**：$x=-10^{38}$、$y=10^{38}$、$z=1$。$(x+y)+z=0+1=1$；但 $x+(y+z)$：$y+z$ 太大，1 被捨掉，還是 $10^{38}$，結果 0。

?? 選擇 | 下面哪一句對？
[ ] IEEE 754 的指數欄位用二補數
[x] 0.1 不能用二進位浮點數精確表示
[ ] 浮點數加法滿足結合律
!! 0.1 寫成二進位是什麼樣子？
>> $0.1=0.000110011\dots_2$ 無限循環。指數用偏移；浮點加法不滿足結合律。

@例題 把 $-0.75$ 寫成單精度浮點數（寫出三個欄位和十六進位）。
@寫 轉二進位、正規化 | $0.75=0.11_2=1.1\times2^{-1}$
@寫 寫出三個欄位 | 符號 1；指數 $-1+127=126=01111110$；尾數 $1000\dots0$（23 位）。
@步 拼起來、四位一組換十六進位 | `1011 1111 0100 0000 … 0000` → `0xBF400000`
@答 `1 01111110 10000000000000000000000` = `0xBF400000`

=== co-perf#1
title: 效能鐵律：CPU 時間 = 指令數 × CPI × 時脈週期
mins: 35
goal: 會用鐵律算 CPU 時間、比較兩台機器；會算平均 CPI；知道為什麼 MIPS 會騙人
---
> [!先記住]
> **CPU 時間 = 指令數 × CPI × 時脈週期**。CPI 是「平均每道指令要幾個時脈週期」。三個因素乘在一起才是真正的時間，只看其中一個（例如時脈頻率）會被騙。

```fig
flow: 指令數 IC | 每道指令幾個週期 CPI | 每個週期多久 T -> 相乘 -> CPU 時間*
```

一個程式在 CPU 上跑多久？三個因素相乘：
$$\text{CPU 時間}=\text{IC}\times\text{CPI}\times T$$
- **IC**：執行了幾條指令
- **CPI**：平均每條指令要幾個時脈週期
- **$T$**：一個時脈週期多長（$T=\frac1f$，$f$ 是時脈頻率，例如 2 GHz）

?? 填空 | 一個程式執行 $10^9$ 條指令、CPI=2、時脈 2 GHz。CPU 時間是幾秒？
== 1
!! $T=\frac{1}{2\times10^9}$ 秒。
>> $10^9\times2\times\frac{1}{2\times10^9}=1$ 秒。

**指令集**（ISA）是 CPU 看得懂的指令清單。三個因素各被誰影響：
- IC：演算法、程式語言、編譯器、指令集
- CPI：編譯器、指令集、**CPU 內部設計**（管線、快取）
- 時脈：CPU 內部設計、**製程**

?? 選擇 | 換一個更聰明的編譯器，可能改變哪些因素？
[x] IC 和 CPI
[ ] 只有時脈
[ ] 三個都不會變
!! 編譯器決定產生哪些指令。
>> 編譯器會改變指令的數量和種類（所以平均 CPI 也變），但不改變硬體時脈。

不同種類的指令 CPI 不一樣。**平均 CPI** 用比例加權：
$$\text{CPI}=\sum_i \text{CPI}_i\times(\text{第 }i\text{ 類占的比例})$$

?? 填空 | 50% 的指令 CPI=1、30% 的 CPI=2、20% 的 CPI=4。平均 CPI 是多少？
== 1.9
!! $0.5\times1+0.3\times2+0.2\times4$。
>> $0.5+0.6+0.8=1.9$。

**比較兩台機器**：算「同一個程式」在兩台的 CPU 時間。$A$ 比 $B$ 快幾倍＝$\frac{\text{時間}_B}{\text{時間}_A}$。

**MIPS 會騙人**：$\text{MIPS}=\frac{f}{\text{CPI}\times10^6}$（每秒幾百萬條指令）。它**不管指令數**：簡單指令集的機器 MIPS 很高，但可能要多很多條指令才做完同一件事。

?? 選擇 | 同時脈下，A 跑 10 億條 CPI=1 的指令、B 跑 6 億條 CPI=1.5 的指令。哪台比較快？
[ ] A，因為 MIPS 比較高
[x] B，因為 $0.6\times1.5=0.9<1$
[ ] 一樣快
!! 比的是 IC × CPI（時脈一樣）。

=== co-perf#2
title: 怎麼平均：算術、調和、幾何平均
mins: 25
goal: 知道比時間用算術平均、比速率用調和平均、比 SPEC ratio 用幾何平均；知道為什麼幾何平均跟參考機器無關
---
> [!先記住]
> 不同種類的指令 CPI 不一樣，**平均 CPI = 各類指令 CPI 的加權平均**（權重是它佔的比例）。MIPS（每秒幾百萬道指令）看起來很直覺，但不能拿來比不同的機器。

```fig
bars
bar ALU: 0.5 0.5
bar 載入: 1 1.0（最多）*
bar 儲存: 0.3 0.3
bar 分支: 0.4 0.4
cap: 每類指令對平均 CPI 的貢獻（比例 × CPI）。要降 CPI，先從貢獻最大的載入下手
```

跑很多個測試程式（**基準** benchmark），要怎麼合成一個分數？看你平均的是什麼：

- **時間**（秒）：用**算術平均**（或加權）——總時間才是真的。
- **速率**（例如 MIPS、每秒幾件）：用**調和平均** $\frac{n}{\sum 1/x_i}$。
- **比值**（例如 SPEC ratio）：用**幾何平均** $\sqrt[n]{\prod x_i}$。

?? 選擇 | 兩個程式各跑 1 秒和 9 秒，平均時間該怎麼算？
[x] 算術平均：5 秒
[ ] 幾何平均：3 秒
[ ] 調和平均：1.8 秒
!! 時間可以直接相加。
>> 總時間 10 秒、兩個程式，平均 5 秒。

為什麼速率要用調和平均？一台車去程時速 60、回程時速 30（距離一樣），平均時速不是 45：
去程花 $d/60$、回程 $d/30$，平均時速 $\frac{2d}{d/60+d/30}=40$，就是 60 和 30 的調和平均。

?? 填空 | 兩段工作量一樣的程式，一段跑出 100 MIPS、一段 50 MIPS。整體平均是幾 MIPS？
== 66.67
== 66.7
== 200/3
!! 調和平均 $\frac{2}{1/100+1/50}$。
>> $\frac{2}{0.03}\approx66.7$，不是 75。

**SPEC ratio**＝參考機器的時間 ÷ 受測機器的時間（越大越好）。很多個程式的 SPEC ratio 用**幾何平均**合起來。

好處：兩台機器幾何平均的**比值**，**跟選哪台當參考機器無關**（參考機器的時間在比值裡會約掉）。算術平均沒有這個性質。

?? 選擇 | 為什麼 SPEC 用幾何平均？
[x] 兩台機器的比較結果不會因為換參考機器而改變
[ ] 幾何平均算起來比較快
[ ] 幾何平均一定比較大
!! $\frac{\sqrt[n]{\prod(r_i/a_i)}}{\sqrt[n]{\prod(r_i/b_i)}}$，$r_i$ 是參考時間。
>> $r_i$ 約掉了，只剩 $\sqrt[n]{\prod(b_i/a_i)}$。

?? 寫 | 在手寫板算：SPEC ratio 是 2、8，幾何平均和算術平均各是多少？
== 幾何：$\sqrt{2\times8}=4$；算術：$(2+8)/2=5$。
!! 幾何平均是相乘開根號。
>> 幾何平均 ≤ 算術平均，只有全部相等時才一樣。

@例題 兩個程式在參考機器跑 10 秒、100 秒；機器 X 跑 5 秒、25 秒。算 X 的 SPEC ratio 和幾何平均。
@寫 兩個 SPEC ratio | $10/5=2$、$100/25=4$。
@寫 幾何平均 | $\sqrt{2\times4}=\sqrt8\approx2.83$。
@步 解讀 | X 整體大約比參考機器快 2.83 倍。
@答 SPEC ratio 2、4；幾何平均約 2.83。

=== co-perf#4
title: 功耗與成本：為什麼時脈不再往上衝
mins: 25
goal: 會用 $P\propto CV^2f$ 算功耗變化；知道 power wall 讓業界轉向多核；知道晶粒越大成本越高
---
> [!先記住]
> **動態功耗** $\propto C\,V^2f$：電壓的影響是平方，所以降電壓最省電。時脈和電壓拉不上去了（**功耗牆**），所以 CPU 改走多核心。比較好幾個程式的效能比，用**幾何平均**。

```fig
bars
bar 原本: 100 100%
bar 頻率降 15%: 85 85%
bar 電壓、頻率都降 15%: 61 61%*
cap: 動態功耗 ∝ V² f：電壓是平方，影響最大
```

CPU 的**動態功耗**：
$$P=\alpha\,C\,V^2 f$$
$C$ 是電容（跟電晶體多寡有關）、$V$ 是電壓、$f$ 是時脈、$\alpha$ 是有多少比例在切換。**電壓的影響是平方**。

?? 填空 | 電壓降成原本的 0.8 倍、時脈不變，動態功耗變成原本的幾倍？
== 0.64
!! $V^2$。
>> $0.8^2=0.64$，省了 36%。

過去 30 年，時脈一直提高，靠的是每一代把電壓降低來壓住功耗。但電壓降到大約 1V 就降不下去了（再低電晶體會漏電），功耗和散熱撞牆——**power wall**。

所以大約 2005 年之後，單核時脈幾乎不再成長，業界改成**一顆晶片放很多核**。

?? 選擇 | 為什麼現在的 CPU 改成多核，而不是一直提高時脈？
[x] 電壓降不下去，提高時脈功耗和散熱會受不了
[ ] 多核比較便宜
[ ] 程式自動會平行
!! 功耗 $\propto V^2f$，$V$ 降不下去時，提高 $f$ 會怎樣？
>> 功耗跟著時脈直線上升，散熱撐不住。多核用比較低的時脈換取總效能——但程式要能平行（上一節的 Amdahl）。

**靜態功耗**：電晶體不切換也會漏電，電晶體越多越大。

**成本**：晶粒（die）切自晶圓（wafer）。
$$\text{每個晶粒的成本}=\frac{\text{晶圓成本}}{\text{每片晶粒數}\times\text{良率}}$$
晶粒越大：每片切得越少，而且越容易碰到缺陷，良率下降——**成本上升比面積快很多**。

?? 選擇 | 晶粒面積變成兩倍，成本大約會？
[ ] 變一半
[ ] 剛好變兩倍
[x] 超過兩倍
!! 每片晶粒數變一半，良率也下降。
>> 兩個效果相乘，成本上升超過兩倍。

?? 寫 | 在手寫板算：電壓降 15%、時脈降 15%，動態功耗變成原本的多少？
== $0.85^2\times0.85=0.85^3\approx0.61$，省了大約 39%。
!! $V^2f$，兩個都乘 0.85。
>> 這就是「降一點時脈，省很多電」的原因。

@例題 新一代 CPU 電容變成 0.85 倍、電壓降 15%，時脈不變。動態功耗是舊的幾倍？
@寫 寫出比值 | $\frac{P_{\text{新}}}{P_{\text{舊}}}=\frac{0.85C\cdot(0.85V)^2\cdot f}{C V^2 f}$
@寫 算出來 | $0.85\times0.85^2=0.85^3\approx0.614$
@步 解讀 | 省了大約 39%；電壓的平方效果占了大部分。
@答 約 0.61 倍。

=== co-datapath#1
title: 指令集設計：RISC vs. CISC、MIPS 與 RISC-V 的格式
mins: 40
goal: 分得清 RISC 和 CISC；會讀 MIPS 的 R、I、J 格式與 RISC-V 的 R、I、S 格式；會算 MIPS 與 RISC-V 分支的目標位址
---
```fig
bits: op 6 | rs 5 | rt 5 | rd 5 | shamt 5 | funct 6
---
bits: op 6 | rs 5 | rt 5 | 立即值 16*
---
bits: op 6 | 位址 26*
cap: 由上到下：R 型（`add $s1, $s2, $s3`）、I 型（lw、sw、beq、addi）、J 型（j、jal）
```

**指令集**（ISA）是 CPU 和軟體之間的約定：有哪些指令、每條長什麼樣子。

- **RISC**（如 MIPS、RISC-V、ARM）：指令**固定長度**、只有 load／store 能碰記憶體（其他都在暫存器之間做）、暫存器多、定址方式少
- **CISC**（如 x86）：指令長度不固定、一條指令可以直接運算記憶體裡的資料

現代 x86 在 CPU 內部會把複雜指令拆成像 RISC 的小指令（micro-ops）。

?? 選擇 | 下面哪一個是 RISC 的特色？
[x] 只有 load、store 能存取記憶體
[ ] 指令長度不固定
[ ] 一條指令可以把兩個記憶體位置相加
!! RISC 讓指令簡單、規律。
>> load/store 架構是 RISC 的招牌。長度不固定、能直接運算記憶體是 CISC。

MIPS 每條指令 32 位元，三種格式：

| 格式 | 欄位（位元數） | 例子 |
|---|---|---|
| R | op(6) rs(5) rt(5) rd(5) shamt(5) funct(6) | `add $t0, $t1, $t2` |
| I | op(6) rs(5) rt(5) immediate(16) | `lw`、`sw`、`beq`、`addi` |
| J | op(6) address(26) | `j` |

?? 填空 | MIPS 有 32 個暫存器。要指定一個暫存器，欄位需要幾個位元？
== 5
!! $2^5=32$。
>> 所以 rs、rt、rd 都是 5 位元。

**分支 `beq rs, rt, label`**：相等就跳。目標位址 $=PC+4+\text{(立即值)}\times4$。
立即值是**指令個數**（不是位元組），所以要乘 4；而且是從 $PC+4$（下一條指令）開始算。

?? 填空 | `beq` 在位址 100，立即值是 3。跳躍的目標位址是多少？
== 116
!! $100+4+3\times4$。
>> $104+12=116$。

**跳躍 `j`**：26 位元的位址乘 4（補兩個 0）變 28 位元，前面接上 $PC+4$ 的最高 4 位元。所以 `j` 只能跳到同一個 256 MB 的區塊裡。

**RISC-V**：台大 110 年起的計結考題用的是它。一樣是 32 位元固定長度、只有 load／store 碰記憶體，但欄位排法和 MIPS 不同：

```fig
bits: funct7 7 | rs2 5 | rs1 5 | funct3 3 | rd 5 | opcode 7
---
bits: imm[11:0] 12* | rs1 5 | funct3 3 | rd 5 | opcode 7
---
bits: imm[11:5] 7* | rs2 5 | rs1 5 | funct3 3 | imm[4:0] 5* | opcode 7
cap: 由上到下：R 型（`add x5, x6, x7`）、I 型（`addi`、`lw`、`jalr`）、S 型（`sw`）
```

- 32 個暫存器 `x0`～`x31`，`x0` 永遠是 0（像 MIPS 的 `$zero`）。
- opcode 在**最低** 7 位元，再用 funct3（3 位元）、funct7（7 位元）細分是哪一種運算。
- rs1、rs2、rd 在每種格式的位置都一樣，硬體不用先解碼就能去讀暫存器。

?? 選擇 | RISC-V 的 opcode 欄在哪裡、幾位元？
[x] 最低的 7 位元
[ ] 最高的 6 位元
[ ] 最低的 6 位元
!! 跟 MIPS 剛好在相反的一端。
>> MIPS 的 op 是最高 6 位元；RISC-V 的 opcode 是第 6～0 位元。

S 型（`sw x5, 8(x6)`）沒有目的暫存器，所以把 12 位元立即值**拆開**：低 5 位元 imm[4:0] 放在 rd 的位置，高 7 位元 imm[11:5] 放在 funct7 的位置。這樣 rs1、rs2 永遠在同一格。分支用的 B 型也是拆開放。另外還有 U 型（`lui`、`auipc`，20 位元立即值）和 J 型（`jal`），一共六種：R、I、S、B、U、J。

?? 填空 | `sw x5, 40(x6)` 的立即值 40 拆開放，imm[4:0] 那一欄是多少（十進位）？
== 8
!! 先把 40 寫成二進位。
>> $40=101000_2$，低 5 位元 $01000_2=8$，高 7 位元 $0000001_2=1$。

分支和跳躍：
- `beq rs1, rs2, offset` 跳到 $PC+\text{offset}$，從**分支自己**的位址算，不是 $PC+4$；offset 以 2 bytes 為單位編碼。
- **沒有分支延遲槽**。
- `jal rd, offset` 把 $PC+4$ 存進 rd 再跳；`jalr rd, imm(rs1)` 跳到 rs1＋imm。函式回傳是 `jalr x0, 0(ra)`。

?? 選擇 | RISC-V 的 `beq` 在位址 100，要跳到 116。offset 代表幾個 bytes？
[x] 16
[ ] 12
[ ] 3
!! RISC-V 從分支自己的位址算。
>> $116-100=16$。同樣的跳躍在 MIPS 是 $(116-104)/4=3$ 個指令。

呼叫慣例（寫組語時用的名字）：`ra`＝`x1` 存回傳位址、`sp`＝`x2` 是堆疊指標、`a0`～`a7` 傳參數（`a0` 也放回傳值）；`t0`～`t6` 由呼叫者自己存，`s0`～`s11` 由被呼叫的函式負責還原。RV64 的暫存器是 64 位元，用 `ld`／`sd` 存取 8 bytes，`lw`／`sw` 存取 4 bytes。

?? 選擇 | 函式 f 呼叫 g 之後，還要用 `s1` 和 `t1` 的舊值。照慣例誰負責保存？
[x] `s1` 由 g 保存（g 有用到才存）；`t1` 由 f 在呼叫前自己存
[ ] 兩個都由 g 保存
[ ] 兩個都不用存，硬體會自動保存

>> s 暫存器是被呼叫者保存（callee-saved）；t 暫存器是呼叫者保存（caller-saved），g 可以隨便改。

設計原則（課本的四條）：簡單有利於規律、越小越快、好設計需要好的折衷、讓常見情況變快。

?? 選擇 | 16 位元有號立即值的 `beq`，最遠能往前或往後跳大約幾條指令？
[x] 大約 $2^{15}$ 條
[ ] 大約 $2^{16}$ 條

title: 單週期資料路徑：控制訊號表
mins: 40
goal: 會寫出 R 型、lw、sw、beq 的控制訊號；會判斷某個訊號卡住時哪些指令壞掉；會算單週期的時脈

> [!先記住]
> **單週期**：每道指令一個週期做完。一道指令依序經過：取指令 → 讀暫存器 → ALU → 讀寫記憶體 → 寫回暫存器。週期要長到**最慢的指令（lw）**也跑得完，所以簡單的指令浪費時間。

```fig
cap: lw 五個步驟都要用到，所以它決定了單週期的時脈週期
```

**資料路徑**：CPU 裡資料流動的路線——PC、指令記憶體、暫存器檔、ALU、資料記憶體，用多工器（MUX）選路。

**單週期**：每條指令**一個時脈週期**做完。控制單元看指令的 op，決定每個 MUX 和元件的開關（**控制訊號**）。

?? 選擇 | `lw $t0, 4($t1)` 的 ALU 要做什麼？

[ ] 減法
[ ] 什麼都不做
!! 要讀的記憶體位址怎麼來？

主要的控制訊號：

| 指令 | RegDst | ALUSrc | MemtoReg | RegWrite | MemRead | MemWrite | Branch |
|---|---|---|---|---|---|---|---|
| R 型 | 1 | 0 | 0 | 1 | 0 | 0 | 0 |
| lw | 0 | 1 | 1 | 1 | 1 | 0 | 0 |
| sw | X | 1 | X | 0 | 0 | 1 | 0 |
| beq | X | 0 | X | 0 | 0 | 0 | 1 |

意思：
- RegDst：寫回 rd（1）還是 rt（0）
- ALUSrc：ALU 第二個輸入是暫存器（0）還是立即值（1）
- MemtoReg：寫回的值來自記憶體（1）還是 ALU（0）
- X：不在乎（反正不寫回）

?? 選擇 | sw 的 RegWrite 是多少？

[ ] 1
[ ] X

**訊號卡住**：如果 RegDst 卡在 0，結果一律寫到 rt——R 型壞掉（它要寫 rd），lw 正常（本來就寫 rt），sw、beq 不寫暫存器不受影響。

?? 選擇 | 如果 ALUSrc 卡在 0，哪一個指令會壞掉？
[ ] R 型
[x] lw 和 sw
[ ] 都不會

>> lw、sw 要算「暫存器＋位移」，卡在 0 會變成「暫存器＋暫存器」。beq 和 R 型本來就是 0。

**時脈**：單週期的時脈要容得下**最慢**的指令。元件延遲（ps）：指令記憶體 200、讀暫存器 100、ALU 200、資料記憶體 200、寫暫存器 100。
- lw：$200+100+200+200+100$ $=800$
- R 型：600（沒有資料記憶體）

所以時脈是 800 ps，其他指令都在空等。

!! 取指令、讀暫存器、ALU、寫記憶體。
>> $200+100+200+200=700$。

?? 寫 | 在手寫板寫出：如果 MemtoReg 卡在 1，哪些指令會壞掉？為什麼？
== R 型壞掉：它的結果在 ALU，卻寫回了記憶體讀出來的值。
== lw 正常（本來就是 1）；sw、beq 不寫暫存器，不受影響。
!! 誰需要把 ALU 的結果寫回暫存器？
>> 考試常考這種「卡住的訊號」題。

=== co-pipeline#1
title: 管線：像洗衣服一樣，好幾條指令同時在不同步驟
mins: 35
goal: 會算 $k$ 級管線跑 $n$ 條指令要幾個週期；知道管線提高的是 throughput、不是單一指令的延遲；分得清結構、資料、控制三種危障
---
> [!先記住]
> **管線**把一道指令切成 5 個階段（IF、ID、EX、MEM、WB），不同指令同時在不同階段。每道指令本身沒有變快，但**每個週期完成一道**，吞吐量變成約 5 倍。

```fig
lanes
指令 1: 0 IF ID EX MEM WB
指令 2: 1 IF ID EX MEM WB
指令 3: 2 IF ID EX MEM WB
指令 4: 3 IF ID EX MEM WB
cap: 5 級管線跑 4 道指令：5 + 4 − 1 = 8 個週期。沒有管線要 4 × 5 = 20 個
```

洗衣服有洗、烘、摺三步。第一批進烘衣機時，第二批就可以開始洗。**每一步都有人在做**，整體快很多。

**管線**：把指令切成 5 級（IF、ID、EX、MEM、WB），每個週期每一級各做一條不同的指令。

**$k$ 級、$n$ 條指令**：第一條要 $k$ 個週期才做完，之後每個週期完成一條：
$$k+n-1\text{ 個週期}$$

?? 填空 | 5 級管線跑 100 條指令（沒有任何等待），需要幾個週期？
== 104
!! $k+n-1$。
>> $5+100-1=104$。

理想的加速比趨近**級數 $k$**（$n$ 很大、每級時間一樣）。實際上會被最慢的那一級、管線暫存器的延遲、還有**危障**拖慢。

**重點**：管線讓「每秒完成幾條」（throughput）變多，**不會讓單一條指令變快**（反而稍慢，因為每級都要等最慢的那級）。

?? 選擇 | 「管線可以縮短單一指令從開始到結束的時間」對嗎？
[ ] 對
[x] 不對
!! 一條指令還是要走完 5 級，而且每級都要用最慢那級的時間。
>> 管線提高的是 throughput。

?? 寫 | 在手寫板算：五個步驟的延遲是 200、100、200、200、100 ps。單週期時脈多少？管線時脈多少？跑 $10^6$ 條指令，加速比大約多少？
== 單週期：$200+100+200+200+100$ $=800$ ps；管線：取最慢一級 200 ps
== 單週期 $800\times10^6$；管線約 $(10^6+4)\times200\approx200\times10^6$；加速比約 4
!! 管線的時脈由最慢的那級決定。
>> 不是 5 倍，因為各級時間不平均。

**危障**（hazard）：讓下一條指令不能在下一個週期開始的情況。
| 種類 | 原因 | 例子 |
|---|---|---|
| 結構危障 | 硬體不夠用 | 只有一個記憶體，取指令和 lw 撞在一起 |
| 資料危障 | 要用前面還沒算好的結果 | `add $t0,...` 接 `sub ...,$t0,...` |
| 控制危障 | 分支還沒決定要不要跳 | `beq` 後面該取哪一條？ |

?? 選擇 | 指令和資料共用一個記憶體，造成 IF 和 MEM 同時要用。這是哪一種危障？
[x] 結構危障
[ ] 資料危障
[ ] 控制危障
!! 是硬體資源不夠，還是資料還沒好？
>> 解法：指令快取和資料快取分開。

5 級**順序**管線中，所有寫入都在 WB、所有讀取都在 ID，所以資料危障只有 **RAW**（先寫後讀）一種。

@例題 4 級管線，每級 250 ps；沒有管線的版本每條指令 1000 ps。跑 1000 條指令，各要多久？加速比？

@步 加速比 | $10^6/250750\approx3.99$，接近級數 4。

**做法 2：提早決定**。在 ID 就比較兩個暫存器、算出目標位址（多加一個比較器），猜錯只浪費 1 拍。

title: Cache：CPU 手邊的小書架

cache 有用，是因為程式有**區域性**：

- **空間區域性**：用了這個，很快會用旁邊的（陣列 `a[0]`、`a[1]`…）

[ ] 兩種都要

=== co-cache#4
title: Cache 的效能公式：AMAT 和 CPI
mins: 35
goal: 會算 AMAT；會把指令 cache 和資料 cache 的失誤算進 CPI；會算兩層 cache 的 AMAT、分得清 local 和 global miss rate
---
> [!先記住]
> **AMAT（平均記憶體存取時間）= 命中時間 + miss 率 × miss 懲罰**。多層 cache 時，L1 的 miss 懲罰就是「去 L2 找的平均時間」，一層一層代進去。

```fig
flow: L1：1 週期 -> 5% miss -> L2：10 週期 -> 20% miss -> 記憶體：100 週期
cap: 越下層越大越慢；大部分存取在 L1 就解決了
```

**平均記憶體存取時間**：
$$\text{AMAT}=\text{hit time}+\text{miss rate}\times\text{miss penalty}$$

?? 填空 | hit time 1 個週期、miss rate 5%、miss penalty 100 個週期。AMAT 是多少週期？
== 6
!! $1+0.05\times100$。
>> 6 個週期——平均起來比命中慢 6 倍。

**算進 CPI**：每條指令平均多等的週期
$$\text{CPI}=\text{CPI}_{base}+\frac{\text{記憶體存取次數}}{\text{指令}}\times\text{miss rate}\times\text{miss penalty}$$
- 指令 cache：**每條指令** 1 次
- 資料 cache：只有 load／store 那個比例

?? 寫 | 在手寫板算：基本 CPI 2；指令 cache miss rate 2%；資料 cache miss rate 4%；load／store 佔 36%；miss penalty 100 週期。實際 CPI？
== 指令：$1\times0.02\times100=2$；資料：$0.36\times0.04\times100=1.44$
== CPI＝$2+2+1.44=5.44$
!! 兩種 cache 分開算再加起來。
>> 理想 cache 時 CPI 2，實際 5.44，慢 2.72 倍。

?? 選擇 | 「提高關聯度一定會降低 AMAT」對嗎？
[ ] 對
[x] 不對
!! 公式裡哪一項會因為關聯度變高而變大？
>> miss rate 降，但 hit time 升，不一定划算。

**兩層 cache**：L1 沒中去問 L2，L2 也沒中才去記憶體：
$$\text{AMAT}=HT_1+MR_1\times(HT_2+MR_2\times MP_2)$$
- $MR_2$ 是 **local** miss rate：「到 L2 的存取」裡有多少沒中
- **Global** miss rate＝$MR_1\times MR_2$：所有存取裡有多少要去記憶體

?? 填空 | L1 miss rate 5%，L2 的 local miss rate 40%。L2 的 global miss rate 是多少？（用小數）
== 0.02
!! 兩個相乘。
>> $0.05\times0.4=0.02$，也就是 2% 的存取會到主記憶體。

L2 的 local miss rate 通常**很高**（容易的都被 L1 接走了）。L1 重 hit time（小、快），L2 重 miss rate（大、關聯度高）。

@例題 基本 CPI 1、時脈 4 GHz、主記憶體 100 ns。每條指令到主記憶體的失誤率 2%。加一個 5 ns 的 L2 之後，到主記憶體的失誤率降到 0.5%。快幾倍？
@寫 換成週期 | 4 GHz 一個週期 0.25 ns：主記憶體 400 週期、L2 20 週期
@寫 前後 CPI | 原本 $1+0.02\times400=9$；加 L2：$1+0.02\times20+0.005\times400=1+0.4+2=3.4$
@步 加速比 | $9/3.4\approx2.6$
@答 快約 2.6 倍。

title: Cache 進階最佳化
mins: 25
goal: 知道 victim cache、prefetch、non-blocking cache、critical word first 各解決什麼；會用 loop interchange 讓陣列存取符合列優先順序；知道 blocking 的想法
---
```fig
plane
range: 0 8 0 6 stretch
seg (0.5,5) (2,3)
seg (2,3) (3.5,2) hl
seg (3.5,2) (5,2.3)

text (5.3,4.8) "太大反而變差" bad

```

降低 AMAT 的三個方向：降 hit time、降 miss rate、降 miss penalty。常見技巧：

**降 miss rate**
- **victim cache**：一個很小的全關聯 cache，放「剛被踢出去的塊」。直接映射的衝突失誤常常馬上又要用回來
- **prefetch**（預取）：猜接下來要用的塊，先搬（硬體看存取模式，或編譯器插指令）
- **編譯器**：loop interchange、blocking（下面）

?? 選擇 | victim cache 主要降低哪一種失誤？
[x] Conflict
[ ] Compulsory
[ ] Capacity
!! 被踢出去又馬上要用回來，是因為什麼被踢？
>> 搶同一格的衝突。

**降 miss penalty**
- **critical word first**：先傳 CPU 要的那個字，CPU 拿到就繼續，其他的慢慢傳
- **non-blocking cache**：一次沒中時，後面別的存取如果命中，可以照常服務（hit under miss）
- **多層 cache**（multilevel cache）：L2、L3

?? 選擇 | 「CPU 等的那個字先送，其他字之後再補」是哪個技巧？
[x] critical word first
[ ] prefetch
[ ] victim cache
!! 名字就是答案。
>> 降低 miss penalty 中 CPU 實際等待的時間。

**Loop interchange**：C 的二維陣列是**列優先**（同一列的元素相鄰）。內層迴圈應該跑**行的索引**：

```c
for (i...) for (j...) x[i][j]   // 好：連續存取
for (j...) for (i...) x[i][j]   // 差：每次跳一整列
```

?? 寫 | 在手寫板算：`int x[1024][1024]`（列優先），塊 64 位元組（16 個 int），cache 很小（一列都放不下）。用「先 j 後 i」和「先 i 後 j」掃一遍，各大約沒中幾次？
== 先 j 後 i：每次跳 4096 位元組，每次都換塊 → 每個元素都沒中，約 $1024\times1024\approx10^6$ 次
== 先 i 後 j：每塊 16 個連續 int，16 次只沒中 1 次 → 約 $10^6/16=65536$ 次
!! 一塊能裝幾個相鄰的 int？
>> 只換了迴圈順序，失誤少了 16 倍。

**Blocking**：矩陣乘法這種要反覆用同一批資料的，把矩陣切成小塊，一次只處理 cache 放得下的那一小塊，用完再換下一塊。

?? 選擇 | 硬體偵測到程式一直依序讀位址 0、64、128、192…，於是先把 256 那塊搬進來。這是什麼技巧？
[x] prefetch
[ ] victim cache
[ ] critical word first
!! 還沒要就先搬。
>> 猜對可以省掉 compulsory 失誤；猜錯會浪費頻寬、還可能把有用的塊擠掉。

@例題 一個程式的 AMAT 是 $1+0.05\times100=6$。三個方案：(A) victim cache 讓 miss rate 降到 4%；(B) critical word first 讓 CPU 實際等待降到 60 週期；(C) 換成更大的 L1，miss rate 降到 3%，但 hit time 變 2。哪一個最好？
@寫 (A)、(B) | (A) $1+0.04\times100=5$；(B) $1+0.05\times60=4$
@寫 (C) | $2+0.03\times100=5$
@步 比較 | (B) 最好；(C) 降了 miss rate，但 hit time 變長抵消掉一部分
@答 (B)，AMAT 降到 4。

=== co-ilp#5

title: TLB、頁表、cache 三者怎麼配合
mins: 35
goal: 會判斷 TLB／頁表／cache 命中與否的組合哪些可能；分得清 PIPT、VIVT、VIPT；會算 VIPT 至少要幾路關聯

> [!先記住]
> 每次存取記憶體都要把虛擬位址翻譯成實體位址，翻譯要查頁表（在記憶體裡），太慢。**TLB** 是一個小小的 cache，記最近用過的「虛擬頁號 → 實體頁框號」，大部分翻譯一個週期就完成。

```fig
flow: 虛擬位址 -> 查 TLB -> 命中：直接得到頁框號* | 沒命中：去讀頁表，再填進 TLB -> 實體位址
```

```fig

---
```

CPU 送出的是**虛擬位址**。存取一次記憶體，要經過三個地方：
1. **TLB**：虛擬頁號 → 實體頁框號（快取最近的轉換）
2. **頁表**：TLB 沒中才查
3. **Cache**：用實體（或虛擬）位址找資料

| TLB | 頁表 | Cache | 可能？ |
|---|---|---|---|
| 中 | — | 中／沒中 | 可能 |
| 沒中 | 中 | 中／沒中 | 可能 |
| 沒中 | 沒中 | 沒中 | 可能（page fault） |
| 沒中 | 沒中 | **中** | **不可能**：頁不在記憶體，資料不會在 cache |

[x] 不可能

| 方式 | 好處 | 問題 |
|---|---|---|
| PIPT（實體 index、實體 tag） | 沒有別名問題 | 要先查完 TLB，慢 |
| VIVT（都用虛擬） | 不用先轉換 | **同義字**：兩個虛擬位址對到同一個實體位址；換行程要清 cache |

$$\frac{\text{cache 大小}}{\text{關聯度}}\le\text{頁大小}$$

!! 頁內位移在轉換時會不會變？

=== co-vm-coherence#2
title: Cache 一致性：MESI
mins: 40
goal: 知道一致性要保證的三件事；分得清 snooping 和 directory；會用 MESI 狀態追蹤讀寫；知道 false sharing
---
> [!先記住]
> 多核心時，同一塊資料可能在好幾個 cache 裡各有一份。一個核心改了，其他人不能繼續用舊的。**窺探（snooping）**協定：大家都聽匯流排，有人要寫就把別人的那份**作廢**。常考 **MESI** 四個狀態。

```fig

flow: I -> 讀，別人也有 -> S -> 自己寫：發作廢 -> M
cap: E 的好處：只有自己有又沒改過時，要寫直接變 M，不用在匯流排上通知
```

多核心各有自己的 cache。核心 A 改了 $x$，核心 B 的 cache 裡還是舊的 $x$——要怎麼保持**一致**？

一致性的要求：
1. 讀到**自己**最後寫的值
2. **別人**的寫入，最後一定會被看到
3. 同一個位址的寫入，大家看到的**順序一樣**

[x] 不對

>> 只管同一個位址；不同位址之間的順序是「記憶體一致性模型」（下一節）。

兩種做法：
- **Snooping**：大家都監聽同一條匯流排，看到別人要寫就處理。簡單、適合核心少
- **Directory**：在記憶體端記錄「每一塊在誰的 cache 裡」，點對點傳訊息，**不用廣播**，可以擴展到很多核

寫入時的策略：**write-invalidate**（叫別人的副本作廢，主流）、write-update（把新值廣播出去，頻寬大）。

| E（Exclusive） | 只有我有、跟記憶體一樣 |
| S（Shared） | 可能很多人有、跟記憶體一樣 |
| I（Invalid） | 無效 |

@例題 兩個執行緒各自把自己的計數器加 100 萬次：`int cnt[2];`，執行緒 $i$ 只碰 `cnt[i]`。cache 區塊 64 位元組。為什麼很慢？怎麼改？
@寫 位置 | `cnt[0]`、`cnt[1]` 相鄰，在同一塊
@寫 發生什麼 | 每次寫都要把對方的那塊作廢 → 每次幾乎都一致性失誤，塊一直來回
@步 改法 | 每個計數器補到 64 位元組（例如 `struct { int c; char pad[60]; } cnt[2];`）
@答 false sharing；把兩個計數器放到不同的 cache 區塊。

=== co-vm-coherence#3
title: 記憶體一致性模型：SC 和 TSO
mins: 30
goal: 知道循序一致性（SC）的定義；知道 TSO 放寬了哪一種順序、為什麼（store buffer）；會判斷經典 litmus test 的結果在 SC、TSO 下可不可能
---
> [!先記住]
> **cache 一致性**管「同一個位址」大家看到一樣；**記憶體一致性**管「不同位址的讀寫，別人看到的先後順序」。最直覺的是**循序一致性（SC）**，但很慢，真實的 CPU 會放寬，所以要用 **fence** 和原子指令來同步。

```fig
flow: 循序一致（最嚴格、最慢） -> TSO：讀可以超車前面的寫 -> 更寬鬆：幾乎都能重排*
cap: 越寬鬆越快，但程式設計師要自己加 fence
```

一致性只管**同一個位址**。**記憶體一致性模型**管的是：**不同位址**的讀寫，別的核心看到的順序。

**循序一致性**（SC）：所有核心的操作，看起來像**某一種交錯**，而且每個核心自己的操作**照程式順序**。最直覺，但硬體很難做快。

?? 選擇 | SC 的意思是？
[x] 所有操作像某種交錯，而且各核心保持自己的程式順序
[ ] 所有核心同時執行
[ ] 每個位址的值都一樣
!! 「循序」指的是什麼的順序？
>> 每個核心內部照程式順序。

**TSO**（x86 用的）：允許「**先 store、後 load（不同位址）**」的 load **先完成**。原因：store 先放進 **store buffer**，不用等它寫進 cache，後面的 load 可以先做。其他順序都保持。

?? 寫 | 在手寫板：初值 $x=y=0$。P1：`x=1; r1=y;`；P2：`y=1; r2=x;`。結果 $r1=r2=0$ 在 SC 下可能嗎？在 TSO 下呢？
== SC：不管怎麼交錯，至少有一邊的 store 在對方的 load 之前 → 不可能兩個都讀到 0
== TSO：兩邊的 store 都還在各自的 store buffer，兩個 load 先執行，都讀到 0 → 可能
!! SC 下列出幾種交錯試試。
>> 這就是 Peterson 演算法在 x86 上要加 `mfence` 的原因。

?? 選擇 | TSO 放寬的是哪一種順序？
[x] store 之後的 load（不同位址）
[ ] load 之後的 load
[ ] store 之後的 store
!! store buffer 讓誰可以先跑？
>> 其他三種順序 TSO 都保持。

?? 選擇 | 程式要在 TSO 上強制「store 完成後才 load」，要加什麼？
[x] 記憶體屏障（fence）
[ ] 更大的 cache
[ ] 更多核心
!! 讓 store buffer 先清空。
>> x86 的 `mfence`。

@例題 初值 $x=y=0$。P1：`x=1; y=1;`；P2：`r1=y; r2=x;`。$r1=1$ 且 $r2=0$ 在 TSO 下可能嗎？
@寫 TSO 保持哪些順序 | P1 的 store→store 保持（$x$ 先於 $y$ 被看見）；P2 的 load→load 保持
@寫 推理 | $r1=1$ 表示 P2 看到了 $y=1$；那 $x=1$ 一定更早被看見，所以 $r2$ 讀到 1
@步 結論 | $r1=1,r2=0$ 不可能
@答 不可能（TSO 只放寬 store→load）。

=== co-vm-coherence#4
title: 同步的硬體原語：LL/SC、自旋鎖
mins: 25
goal: 知道 LL/SC 怎麼做到原子的「讀改寫」；知道 test-and-test-and-set 為什麼比直接 test-and-set 好；分得清 UMA 和 NUMA
---
> [!先記住]
> **cache 一致性**管「同一個位址」大家看到一樣；**記憶體一致性**管「不同位址的讀寫，別人看到的先後順序」。最直覺的是**循序一致性（SC）**，但很慢，真實的 CPU 會放寬，所以要用 **fence** 和原子指令來同步。

```fig
flow: 循序一致（最嚴格、最慢） -> TSO：讀可以超車前面的寫 -> 更寬鬆：幾乎都能重排*
cap: 越寬鬆越快，但程式設計師要自己加 fence
```

多核心上的鎖需要**原子**的「讀＋改＋寫」。除了 test_and_set、compare_and_swap，還有一對指令：

**LL/SC**（load-linked／store-conditional）：
- LL：讀一個位址，並且「盯住」它
- SC：寫回去——**如果中間有人寫過這個位址，SC 就失敗**（回傳 0），要重來

?? 選擇 | LL 讀了 $x$ 之後，別的核心寫了 $x$。接著 SC 會怎樣？
[x] 失敗，什麼都不寫
[ ] 成功，蓋掉別人的值
[ ] 等別人寫完再寫
!! SC 的「conditional」是什麼條件？
>> 失敗就重新 LL、重算、再 SC。

?? 寫 | 在手寫板用 LL/SC 寫原子的 `x = x + 1`。
== `retry: r = LL(x); r = r + 1; if (SC(x, r) == 0) goto retry;`
== 中間沒人碰 $x$，SC 成功；有人碰過，就重來
!! 跟 compare_and_swap 的「失敗就重試」一樣的想法。
>> 好處是不用像 CAS 那樣比較值，也不會有「值變回原樣」看不出來的問題。

**x86-64 的原子讀改寫**：對一般可快取記憶體，`lock add` 可把一次記憶體讀、加法、寫回合成原子操作；普通的分開讀與寫沒有這個保證。locked 操作也會排序前後的一般讀寫，但不是把所有其他核心凍結。自然對齊、完整位於同一快取區塊的運算，通常利用快取一致性保護該區塊，不能說成必須跳過所有快取。

?? 選擇 | 64 位元計數器起初九，兩核心各完成一次原子加一，沒有其他寫入。最後是多少？
[x] 11
[ ] 10
[ ] 9
!! 兩次成功操作都必須算進去。
>> 九加一加一為十一；如果拆成普通讀寫，才可能因交錯而遺失更新。

**自旋鎖**：一直試著拿鎖。直接 `while (test_and_set(&lock));` 的問題：每次 test_and_set 都是**寫入**，會一直把別人 cache 裡的鎖作廢，匯流排塞爆。

**test-and-test-and-set**：先**讀**（在自己的 cache 裡讀，不會產生流量），看到鎖是空的才做 test_and_set：

```c
while (1) {
  while (lock == 1) ;              // 在自己的 cache 上空轉
  if (test_and_set(&lock) == 0) break;
}
```

?? 選擇 | test-and-test-and-set 比直接 test_and_set 好在哪裡？
[x] 等的時候只讀自己的 cache，不產生一致性流量
[ ] 拿到鎖比較快
[ ] 不需要原子指令
!! 讀 S 狀態的區塊需要上匯流排嗎？
>> 鎖被釋放（被寫）時才會失效、重新讀。

**UMA**：每個核心存取記憶體的時間一樣（對稱多處理器）。**NUMA**：記憶體分散在各處，存取**遠端**的比較慢——程式要注意資料放在哪個節點。

?? 選擇 | 「directory 協定需要廣播」對嗎？
[ ] 對
[x] 不對
!! directory 記錄了誰有這一塊。
>> 只傳給有副本的人，所以能擴展。

@例題 8 個核心在等同一把鎖。用直接 test_and_set 和 test-and-test-and-set，鎖被持有的這段時間各會產生多少匯流排流量？
@寫 直接 test_and_set | 每個核心每次都在寫 → 鎖的那塊在 8 個 cache 間不停被作廢、搬動，流量很大
@寫 test-and-test-and-set | 第一次讀之後，8 個核心都有 S 狀態的副本，在自己 cache 裡空轉 → 幾乎沒有流量
@步 鎖被釋放時 | 釋放寫入作廢所有副本，8 個核心重新讀、搶 test_and_set，只有一個成功
@答 前者持續大量流量；後者只在釋放時有一波流量。
