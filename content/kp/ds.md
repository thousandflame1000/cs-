=== ds-amortized#1
title: 堆疊與佇列的實作：環狀佇列、兩個堆疊做佇列
mins: 35
goal: 會用陣列做堆疊和環狀佇列；分得出環狀佇列的「滿」和「空」；知道兩個堆疊怎麼做出佇列
---
> [!先記住]
> **堆疊（stack）**：疊盤子，最後放上去的先拿走（LIFO）。**佇列（queue）**：排隊，先來的先走（FIFO）。

```fig
array
row 環狀佇列: _ _ 30 40 50 _
idx: 0 1 2 3 4 5
cap: n = 6，front = 1（指向第一個元素的前一格），rear = 4（最後一個元素）。元素個數 = (rear − front + n) mod n = 3
```

地基學過堆疊（後進先出）和佇列（先進先出）的**用法**。這一節看考試愛考的**實作細節**。

**用陣列做堆疊**：一個 `top` 記住最上面在哪一格。
```
int s[N], top = -1;          // -1 代表空
void push(int x) { s[++top] = x; }
int  pop()       { return s[top--]; }
```
易錯點：堆疊空的時候 pop、滿的時候 push，都要先檢查。

?? 填空 | `top = -1` 開始，依序 push 4、push 7、pop、push 9。現在 `top` 是多少？
== 1
!! 每 push 一次 top 加 1、pop 一次減 1。
>> −1 → 0 → 1 → 0 → 1。堆疊裡是 4、9。

**用陣列做佇列**會遇到一個問題：一直從前面拿、從後面放，前面空出來的格子用不到。解法是**環狀佇列**：走到最後一格就繞回第 0 格，用 `% n`（取餘數）做到。

```
front = rear = 0;           // front：第一個元素的「前一格」
enqueue: rear = (rear + 1) % n;  q[rear] = x;
dequeue: front = (front + 1) % n; return q[front];
```

?? 選擇 | $n=5$，`rear = 4` 時再 enqueue 一個，`rear` 變成多少？
[ ] 5
[x] 0
[ ] 4
!! $(4+1)\bmod5$。
>> 繞回第 0 格，這就是「環狀」。

考試最愛考：**滿和空怎麼分？**
- 空：`front == rear`
- 滿：`(rear + 1) % n == front`

如果讓 $n$ 格全部裝滿，滿的時候 `rear` 也會等於 `front`，跟空分不出來。所以這種寫法**最多只能裝 $n-1$ 個**。要裝滿 $n$ 個，就得另外記一個 `count`。

?? 選擇 | 陣列有 8 格的環狀佇列（只用 front、rear 兩個變數），最多能放幾個元素？
[ ] 8
[x] 7
[ ] 6
!! 空的條件是 `front == rear`，裝滿 8 個時 rear 會在哪裡？
>> 犧牲一格來區分滿和空，最多 7 個。

**用兩個堆疊做佇列**：enqueue 一律 push 進 $S_1$；dequeue 時，如果 $S_2$ 是空的，就把 $S_1$ 全部倒進 $S_2$（順序剛好反過來），再從 $S_2$ pop。

單次 dequeue 最壞要搬 $n$ 個，是 $\Theta(n)$。但**每個元素一輩子只會被搬一次**，所以平均每次操作是 $O(1)$——這叫**攤銷** $O(1)$，下面第 4 節會正式學。

?? 選擇 | 兩個堆疊做佇列：enqueue 1、2、3，然後 dequeue。$S_1$ 倒進 $S_2$ 之後，$S_2$ 最上面是？
[x] 1
[ ] 3
[ ] 2
!! $S_1$ 由下往上是 1、2、3；一個一個 pop 出來再 push 進 $S_2$。
>> 從 $S_1$ pop 的順序是 3、2、1，push 進 $S_2$ 後最上面是 1，正好是最早進來的。

@例題 $n=6$ 的環狀佇列，一開始 `front = rear = 0`。依序 enqueue A、B、C、D，dequeue 兩次，enqueue E、F、G。寫出每個元素放在第幾格，以及最後 `front`、`rear` 的值。再 enqueue 一個會怎樣？
@寫 enqueue A–D 之後 | A 在 1、B 在 2、C 在 3、D 在 4；rear = 4，front = 0。
@寫 dequeue 兩次之後 | 拿走 A、B，front = 2。
@寫 enqueue E、F、G 放在哪幾格？ | E 在 5，F 在 $(5+1)\bmod6=0$，G 在 1；rear = 1。
@步 再 enqueue 會怎樣？ | 檢查 $(1+1)\bmod6=2$ 等於 front，佇列已滿（6 格只能放 5 個）。
@答 front = 2、rear = 1，佇列裡 C、D、E、F、G 共 5 個，已經滿了。

=== ds-amortized#2
title: 運算式：中序轉後序、用堆疊求值
mins: 35
goal: 會把中序式轉成後序式（含括號、優先序、右結合）；會用堆疊算後序式
---
> [!先記住]
> **後序式**（運算子放在兩個數字後面，例如 `3 4 +`）不需要括號，用一個堆疊從左掃到右就能算出答案。把平常的寫法轉成後序，也只要一個堆疊。

```fig
array
row 讀 3、4: 3 4*
row 讀 +: 7*
row 讀 2: 7 2*
row 讀 ×: 14*
cap: 算 3 4 + 2 ×：每一列是讀完一個符號後的堆疊（右邊是頂端）
```

我們平常寫 `a + b * c`，運算子在中間，叫**中序式**。要靠括號和「先乘除後加減」才知道先算誰。

**後序式**把運算子放在兩個運算元後面：`a b c * +`。好處是**不需要括號**，由左往右用一個堆疊就能算。

?? 選擇 | `a + b * c` 的後序式是？
[ ] `a b + c *`
[x] `a b c * +`
[ ] `+ a * b c`
!! 先算 `b * c`，後序寫成 `b c *`；再跟 a 相加。
>> `a (b c *) +` → `a b c * +`。運算子寫在最前面的是前序式。

**後序式求值**：由左往右掃——
- 遇到數字：push
- 遇到運算子：pop 兩個出來算，**先 pop 出來的是右邊那個**，算完 push 回去

?? 填空 | 算後序式 `6 2 / 3 +` 的值。
== 6
!! 遇到 `/` 時 pop 出 2（右）、6（左）。
>> $6/2=3$，push 3；遇到 `+`：$3+3=6$。

?? 填空 | 算後序式 `5 1 2 + 4 * + 3 -`。
== 14
!! 一步一步寫出堆疊：遇到 `+` 先算 $1+2$。
>> $1+2=3$ → $3\times4=12$ → $5+12=17$ → $17-3=14$。

**中序轉後序**（用一個運算子堆疊）：
- 數字：直接輸出
- `(`：push
- `)`：一直 pop 並輸出，直到碰到 `(`（丟掉括號）
- 運算子 $o$：先把堆疊頂端**優先序比 $o$ 高或一樣**的 pop 出來輸出，再 push $o$
- 最後把堆疊剩下的全部 pop 輸出

例外：`^`（次方）是**右結合**，`2^3^2` 是 `2^(3^2)`，所以遇到 `^` 時，堆疊頂端的 `^` **不**pop。

?? 選擇 | 把 `(a + b) * c` 轉成後序。
[x] `a b + c *`
[ ] `a b c + *`
[ ] `a + b c *`
!! 括號裡的先算完。
>> `(a+b)` → `a b +`，再乘 c：`a b + c *`。

?? 選擇 | `a - b - c` 的後序式是？（減法是左結合）
[x] `a b - c -`
[ ] `a b c - -`
!! 左結合：`(a - b) - c`。遇到第二個 `-` 時，堆疊頂端的 `-` 優先序一樣，要先 pop。
>> 第二個 `-` 進來時先把第一個 `-` pop 出來：`a b - c -`。如果寫成 `a b c - -`，那是 `a - (b - c)`，答案不一樣。

@例題 把 `a * (b + c) - d / e` 轉成後序式，寫出每一步堆疊的內容。
@寫 處理到 `(b + c)` 結束時，輸出和堆疊各是什麼？ | 輸出 `a b c +`；堆疊：`*`（`(` 已經跟 `)` 一起丟掉）。
@寫 處理 `-`：要先 pop 誰？ | 頂端 `*` 優先序比 `-` 高，pop 輸出：`a b c + *`；push `-`。
@步 處理 `d / e` 和結尾 | 輸出 d；`/` 比 `-` 高，直接 push；輸出 e；最後依序 pop `/`、`-`。
@答 `a b c + * d e / -`

=== ds-amortized#3
title: 堆疊排列：哪些順序做得出來
mins: 25
goal: 會判斷一個排列能不能用堆疊得到；知道 312 型樣做不出來
---
> [!先記住]
> $1,2,\dots,n$ 照順序進堆疊、隨時可以 pop，能得到的輸出順序有 **Catalan 數** $C_n$ 種；排不出來的，是裡面藏著「312 型」的順序。

```fig
array
row 想輸出 3: 1 2 3*
row pop 3 後: 1 2!
cap: 輸出 3 之後，頂端是 2，不可能先拿到 1。所以 3 1 2 排不出來
```

把 $1,2,\dots,n$ **依序**推進一個堆疊，中間隨時可以 pop 輸出。輸出的順序叫**堆疊排列**。

例：$n=3$，push 1、pop、push 2、push 3、pop、pop → 輸出 `1 3 2`。

?? 選擇 | $n=3$，哪一個做得出來？
[x] `2 1 3`
[ ] `3 1 2`
!! 要先輸出 3，1 和 2 會在哪裡？
>> `2 1 3`：push 1、push 2、pop 2、pop 1、push 3、pop 3。`3 1 2`：輸出 3 時 1、2 都還在堆疊裡，2 壓在 1 上面，下一個一定是 2，不可能是 1。

判斷方法：**模擬**。依序看要輸出的數 $x$：
- 如果 $x$ 還沒 push 過：把到 $x$ 為止的數都 push，再 pop $x$。
- 如果 $x$ 已經在堆疊裡：它必須正好在**最上面**，否則做不到。

?? 選擇 | $n=4$，`3 2 4 1` 做得出來嗎？
[x] 做得出來
[ ] 做不出來
!! 一步一步模擬：輸出 3 要 push 1、2、3。
>> push 1,2,3 pop 3；pop 2（在最上面）；push 4 pop 4；pop 1。做得出來。

規律：一個排列做**不**出來，正好是因為裡面藏著「**大、小、中**」的型樣——位置 $i<j<k$ 的三個數 $p_i>p_k>p_j$（像 `3 1 2`）。

?? 選擇 | `4 1 3 2` 做得出來嗎？
[ ] 做得出來
[x] 做不出來
!! 找找看有沒有「大、小、中」：4、1、然後一個介於 1 和 4 之間的數。
>> 4、1、3 就是「大、小、中」。模擬：輸出 4 時 1、2、3 都在堆疊，3 在最上面，下一個只能是 3，不能是 1。

$n$ 個數的堆疊排列共有幾種？$n=1,2,3,4$ 時是 $1,2,5,14$。這串數叫 **Catalan 數**，之後在離散的計數會正式學它的公式。

?? 填空 | $n=3$ 時，6 種排列裡有幾種做得出來？
== 5
!! 只有一種藏著「大、小、中」。
>> 只有 `3 1 2` 做不出來，6 − 1 = 5。

@例題 判斷 `2 4 3 1` 和 `3 1 4 2` 能不能用堆疊得到。
@寫 模擬 `2 4 3 1` | push 1,2 pop 2；push 3,4 pop 4；pop 3（最上面）；pop 1（最上面）。做得出來。
@寫 模擬 `3 1 4 2` | push 1,2,3 pop 3；下一個要 1，但最上面是 2——做不出來。
@步 用型樣檢查 | `3 1 4 2` 裡 3、1、2 是「大、小、中」，一定做不出來；`2 4 3 1` 找不到這種型樣。
@答 `2 4 3 1` 可以，`3 1 4 2` 不行。

=== ds-amortized#4
title: 攤銷分析：一串操作的平均，三種算法
mins: 40
goal: 分得清攤銷和平均情況；會用聚集法、會計法、位能法分析 MULTIPOP 和二進位計數器
---
> [!先記住]
> **攤銷分析**：一整串操作在**最壞情況**下的總成本，除以操作次數。它不靠運氣、不用機率。三種算法：直接加總（聚集法）、預先多收錢（記帳法）、位能法。

```fig
bars
bar 第 0 位: 8 每次都翻：8 次
bar 第 1 位: 4 每 2 次翻一次：4
bar 第 2 位: 2 每 4 次翻一次：2
bar 第 3 位: 1 每 8 次翻一次：1
cap: 從 0 做 8 次 INCREMENT：總共翻 8 + 4 + 2 + 1 = 15 次 < 2 × 8
```

有些操作**偶爾很貴、大部分很便宜**。只看最壞的一次會太悲觀。**攤銷分析**算的是：**最壞情況下，$n$ 次操作的總成本除以 $n$**。

重點：攤銷**不牽涉機率**——它保證任何一串操作都不會超過這個總和。（「平均情況分析」才是假設輸入隨機。）

?? 選擇 | 「某操作攤銷 $O(1)$」代表什麼？
[ ] 每一次操作都是 $O(1)$
[x] 任何 $n$ 次操作的總成本是 $O(n)$
[ ] 輸入隨機時，平均是 $O(1)$
!! 攤銷是在整串操作上平均，而且不假設隨機。
>> 單次可能很貴（例如 $\Theta(n)$），但總和保證 $O(n)$。

先看影片：陣列滿了就換兩倍大的，插入到底慢不慢。

@影片 ds-amortized 0-65.3

例子：**MULTIPOP 堆疊**。除了 push、pop，還有 `multipop(k)`：一次 pop $k$ 個，成本 $k$。單次 multipop 最壞 $\Theta(n)$，那 $n$ 次操作最壞 $O(n^2)$ 嗎？

**聚集法**：直接算總和。每個元素**最多被 push 一次、pop 一次**，所以 $n$ 次操作總共 pop（包含 multipop 裡的）不超過 push 的次數 $\le n$。總成本 $O(n)$，每次攤銷 $O(1)$。

?? 選擇 | 用聚集法分析 MULTIPOP 時，關鍵的觀察是？
[ ] multipop 很少被呼叫
[x] 每個元素只能被 pop 一次，pop 的總次數不超過 push 的次數
[ ] 堆疊大小有上限
!! 一個元素被 pop 之後還在堆疊裡嗎？
>> 不管怎麼 multipop，總 pop 數 ≤ 總 push 數 ≤ $n$。

再看影片：每次多付一點，存起來給搬家用。

@影片 ds-amortized 65.4-133.9

?? 選擇 | 加倍陣列每次插入收 3 枚金幣，為什麼搬家時一定付得起？
[x] 上次搬家後新放進來的元素，每個存了 2 枚：一枚搬自己、一枚搬一個舊元素
[ ] 搬家很少發生，可以不算
[ ] 3 是隨便選的，任何常數都可以
!! 從 8 格搬到 16 格時，上次搬家之後新放進來幾個？舊的有幾個？
>> 上次搬家（4 → 8）之後新放了 4 個，存了 8 枚；這次要搬 8 個，剛好付得起。收 1 或 2 枚就會不夠。

**會計法**：每種操作預先「收費」$\hat c$，多收的錢存在資料上（叫 credit），之後貴的操作用存款付。只要**任何時刻存款都不是負的**，總收費就是總成本的上界。

MULTIPOP：push 收 2 元——1 元付自己，1 元存在那個元素身上。pop、multipop 收 0 元，用元素身上的 1 元付。

**位能法**：定義一個「位能」$\Phi$（資料結構的狀態值），攤銷成本 $\hat c_i=c_i+\Phi_{\text{後}}-\Phi_{\text{前}}$。只要 $\Phi$ 永遠 $\ge$ 一開始的值，攤銷總和就是實際總和的上界。MULTIPOP 取 $\Phi=$ 堆疊大小：multipop $k$ 個，實際 $k$、位能降 $k$，攤銷 0。

?? 選擇 | 位能法要求位能函數滿足什麼？
[ ] $\Phi$ 最後要回到 0
[x] 任何時刻 $\Phi(D_i)\ge\Phi(D_0)$
[ ] $\Phi$ 可以是負的，只要平均是正的
!! 攤銷總和 = 實際總和 + $\Phi_{\text{最後}}-\Phi_{\text{開始}}$。要它是上界，需要什麼？
>> $\sum\hat c_i=\sum c_i+\Phi(D_n)-\Phi(D_0)$，只要 $\Phi(D_n)\ge\Phi(D_0)$，攤銷總和就 ≥ 實際總和。

經典第二題：**二進位計數器** INCREMENT（加 1）。成本＝翻轉的位元數。`0111` 加 1 變 `1000`，翻 4 個，最壞 $\Theta(k)$。

聚集法：第 0 位每次都翻、第 1 位每 2 次翻一次、第 $i$ 位每 $2^i$ 次翻一次。$n$ 次總共 $<n+\frac n2+\frac n4+\cdots<2n$。攤銷 $O(1)$。

?? 填空 | 從 0 開始做 8 次 INCREMENT（計數器有 4 位），第 1 位（從右數第二位，值是 2 的那位）總共翻了幾次？
== 4
!! 第 1 位每 2 次翻一次。
>> $8/2=4$ 次。全部位元加起來：$8+4+2+1=15<2\times8$。

@例題 用位能法證明二進位計數器 INCREMENT 攤銷 $O(1)$。取 $\Phi=$ 計數器裡 1 的個數。
@寫 某次 INCREMENT 把最右邊連續 $t$ 個 1 變成 0、再把一個 0 變成 1。實際成本是多少？ | $c=t+1$。
@寫 位能變化是多少？ | 少了 $t$ 個 1、多了 1 個：$\Delta\Phi=1-t$。
@步 攤銷成本 | $\hat c=c+\Delta\Phi=(t+1)+(1-t)=2$。而且 $\Phi\ge0=\Phi(D_0)$，所以 $n$ 次總成本 $\le2n$。
@答 每次攤銷 2，$n$ 次 INCREMENT 總共 $O(n)$。

=== ds-amortized#5
title: 動態表：滿了就加倍，為什麼平均 O(1)
mins: 30
goal: 知道「加倍」攤銷 $O(1)$、「加常數」不行；知道縮表要在 1/4 才縮
---
> [!先記住]
> 陣列滿了就換一個**兩倍大**的，把舊的全部搬過去。搬家很貴但越來越少發生，每次插入攤銷 $O(1)$。

```fig
array
row 大小 1: 1*
row 大小 2: 1 2*
row 大小 4: 1 2 3* _
row 大小 8: 1 2 3 4 5* _ _ _
cap: 藍色那一次觸發搬家：要搬的數量 = 舊表大小（1、2、4……）
```

陣列大小是固定的。放滿了怎麼辦？開一個更大的新陣列，把舊的**全部搬過去**。搬家很貴（$n$ 個元素就搬 $n$ 次），所以關鍵是：**新陣列要開多大**？

?? 選擇 | 陣列大小 8、已經放滿，再插入第 9 個。如果策略是「加倍」，這次插入要搬幾個元素？
[ ] 1
[x] 8
[ ] 16
!! 搬家要把舊陣列的每一個都搬過去。
>> 開一個 16 格的新陣列，搬 8 個，再放第 9 個。

**加倍策略**：大小 $1,2,4,8,\dots$。插入 $n$ 個時，搬家的總次數是 $1+2+4+\cdots+\frac n2<n$。再加上 $n$ 次放入，總共 $<3n$——攤銷每次 $O(1)$（大約 3）。

**加常數策略**：每次只多開 $c$ 格。搬家發生在 $c,2c,3c,\dots$，總搬移 $c+2c+\cdots+n\approx\frac{n^2}{2c}$，是 $\Theta(n^2)$——攤銷 $\Theta(n)$。

?? 選擇 | 每次滿了就多開 100 格，插入 $n$ 個元素的總成本是？
[ ] $O(n)$
[ ] $O(n\lg n)$
[x] $\Theta(n^2)$

=== ds-bst#1
title: 二元樹：節點數、高度、四種走訪
mins: 35
goal: 會算節點數與高度的關係、用 $n_0=n_2+1$；會寫前序、中序、後序、層序；知道哪兩種走訪能還原一棵樹
---
> [!先記住]
> **二元樹**：每個節點最多兩個小孩。最常考三個數字：第 $i$ 層最多 $2^i$ 個點；葉子數＝「有兩個小孩的點數」＋1；$n$ 個點有 $n+1$ 個空指標。

```fig
tree
A(B(D,E),C(,F))
cap: 根是第 0 層。葉子 D、E、F 共 3 個；有兩個小孩的是 A、B 共 2 個：3 = 2 + 1
```

**二元樹**：每個節點最多兩個孩子（左、右）。最上面是**根**，沒有孩子的是**葉子**。根在第 0 層，**高度**是最深的葉子在第幾層。

每往下一層，節點數最多加倍：第 $i$ 層最多 $2^i$ 個；高度 $h$ 的樹最多 $1+2+\cdots+2^h=2^{h+1}-1$ 個節點。

?? 填空 | 高度 3 的二元樹，最多有幾個節點？
== 15
!! $2^{h+1}-1$，$h=3$。
>> $2^4-1=15$。

反過來：$n$ 個節點，高度至少 $\lfloor\lg n\rfloor$。**完全二元樹**（每層從左到右填滿）剛好就是這麼矮：高度 $\lfloor\lg n\rfloor$。

一條很常考的式子：設 $n_0,n_1,n_2$ 是有 0、1、2 個孩子（**度數** 0、1、2）的節點數，那
$$n_0=n_2+1$$
證明：每個節點（除了根）上面都有一條邊，邊數 $=n-1$；從孩子算，邊數 $=n_1+2n_2$。兩式相等，再用 $n=n_0+n_1+n_2$ 消掉就得到。

?? 填空 | 一棵二元樹有 10 個葉子，有幾個節點有兩個孩子？
== 9
!! 用 $n_0=n_2+1$。
>> $n_2=n_0-1=9$。

**走訪**：每個節點都拜訪一次。差別只在「根」排在什麼時候：
- **前序**：根、左、右
- **中序**：左、根、右
- **後序**：左、右、根
- **層序**：一層一層、由左到右（用佇列）

都是遞迴定義：「左」指的是「把整個左子樹用同樣的方法走完」。

?? 選擇 | 樹：根 A，A 的左孩子 B、右孩子 C，B 的左孩子 D。中序走訪是？
[ ] A B D C
[x] D B A C
[ ] D B C A
!! 中序：左、根、右。A 的左子樹（B、D）先走完。
>> 左子樹中序：D、B；然後根 A；再右子樹 C。前序是 A B D C，後序是 D B C A。

**給兩種走訪，能不能畫回唯一的樹？**中序能分出「哪些在左、哪些在右」，所以**前序＋中序**、**後序＋中序**都可以。但**前序＋後序不行**：只有根和一個孩子時，孩子在左或在右，前序、後序都一樣。

?? 選擇 | 前序 A B C、中序 B A C。這棵樹的後序是？
[x] B C A
[ ] C B A
[ ] A C B
!! 前序第一個是根 A；中序裡 A 左邊的是左子樹，右邊的是右子樹。
>> 根 A，左子樹 {B}、右子樹 {C}。後序：B、C、A。

@例題 前序是 `A B D E C F`，中序是 `D B E A F C`。畫出這棵樹，並寫出後序。
@寫 根是誰？中序裡左、右子樹各有哪些？ | 根 A（前序第一個）；中序 A 左邊 `D B E` 是左子樹，右邊 `F C` 是右子樹。
@寫 對左子樹（前序 `B D E`、中序 `D B E`）再做一次 | 根 B，左孩子 D、右孩子 E。
@寫 對右子樹（前序 `C F`、中序 `F C`）再做一次 | 根 C，F 在 C 的左邊，所以 F 是 C 的左孩子。
@答 A 的左孩子 B（孩子 D、E），右孩子 C（左孩子 F）。後序：`D E B F C A`。

=== ds-bst#2
title: 二元搜尋樹（BST）：左小右大
mins: 35
goal: 會在 BST 上搜尋、插入、刪除（含兩個孩子的刪除）；知道時間是 $O(h)$、什麼時候會退化成一條鏈
---
> [!先記住]
> **BST**：每個節點，左子樹全部比它小、右子樹全部比它大。找、插、刪都是沿著一條路往下走，時間 $O(h)$。所以重點是樹的高度 $h$。

```fig
tree
1(,2(,3(,4!)))
---
tree
3*(2(1,),4)
cap: 同樣存 1、2、3、4。照順序插入會長成一條線（左，h = 3）；換個順序就很矮（右，h = 2）
```

**二元搜尋樹**：每個節點的**左子樹都比它小、右子樹都比它大**。所以**中序走訪會由小到大**。

搜尋 $x$：從根開始，$x$ 比較小就往左、比較大就往右，直到找到或走到空。路徑長度最多是高度 $h$，所以是 $O(h)$——跟二分搜尋同一個想法。

?? 選擇 | BST 根是 50，左孩子 30、右孩子 70，30 的右孩子是 40。找 45 會經過哪些節點？
[x] 50 → 30 → 40 → 找不到
[ ] 50 → 70 → 找不到
[ ] 50 → 30 → 找不到
!! 45 比 50 小往左，比 30 大往右……
>> 45<50 往左到 30；45>30 往右到 40；45>40 往右是空，找不到。

**插入**：照搜尋的路走到空的地方，放在那裡。

**插入順序決定形狀**：依序插入 1、2、3、4、5，每個都比前一個大，全部往右，變成一條鏈，高度 $n-1$，搜尋變 $O(n)$。隨機順序插入的話，期望高度是 $O(\lg n)$。

?? 選擇 | 依序插入 3、1、4、2，2 會在哪裡？
[ ] 3 的左孩子
[x] 1 的右孩子
[ ] 4 的左孩子
!! 2 跟 3 比、再跟 1 比。
>> 2<3 往左到 1；2>1 往右，1 的右邊是空，放這裡。

**刪除**分三種：
- 葉子：直接拿掉。
- 一個孩子：讓孩子接上來取代它。
- **兩個孩子**：找它的**中序後繼**（右子樹裡最小的，一直往左走到底），把值換過來，再刪掉那個後繼（後繼最多只有右孩子，回到前兩種）。

[x] $z$ 的右子樹裡最小的
[ ] $z$ 的父親
!! 中序裡緊接在 $z$ 後面的那個，一定在哪一邊？
>> 右子樹裡最小的（右子樹一直往左走到底）。用左子樹最大的（中序前驅）也可以。

?? 選擇 | BST 裡依序呼叫「找最小值，然後一直找後繼」把 $n$ 個都走完，總共要多少時間？
[ ] $O(n\lg n)$
[x] $\Theta(n)$
[ ] $O(n^2)$
!! 這等於做一次中序走訪；每條邊最多被走過幾次？
>> 每條邊最多往下走一次、往上走一次，總共 $O(n)$。

?? 寫 | 在手寫板畫出依序插入 `5, 3, 8, 4, 9` 的 BST，再寫出它的中序走訪。
== 5 是根；3 在左、8 在右；4 是 3 的右孩子；9 是 8 的右孩子。
== 中序：3, 4, 5, 8, 9（由小到大）

BST 會退化成鏈。**AVL 樹**多加一個規定：**每個節點左、右子樹的高度差最多 1**（左高減右高叫**平衡因子**，只能是 −1、0、1）。

> [!先記住]
> 紅黑樹不要求完全平衡，只保證**最長的路不超過最短的路的 2 倍**，所以高度 $\le2\lg(n+1)$。好處是插入、刪除需要的旋轉次數很少（插入 ≤ 2、刪除 ≤ 3）。

```fig
tree
[13](8!([1](,6!),[11]),17!([15],[25]))
cap: 方框是黑點、紅圈是紅點。從根往下的每條路都經過 2 個黑點（13 和下面一個）
```

**紅黑樹**是另一種平衡的 BST，用「顏色」管高度。五條規則：
1. 每個節點是紅或黑
2. 根是黑的
3. 空的葉子（NIL）都算黑的
4. **紅節點的孩子一定是黑的**（不能連續兩個紅）
5. 從任一節點往下走到每個葉子，**經過的黑節點數一樣多**（叫**黑高**）

?? 選擇 | 哪一個違反紅黑樹規則？
[ ] 根黑，兩個孩子都紅
[x] 根黑，左孩子紅，左孩子的左孩子也紅
[ ] 全部節點都黑，而且所有葉子同深度
!! 規則 4：紅的孩子要黑。
>> 連續兩個紅違反規則 4。全黑而且完美平衡的那棵是合法的。

為什麼這樣就夠矮？規則 4 讓紅的不能連在一起，所以**任何路徑上紅的最多跟黑的一樣多**；規則 5 讓每條路的黑節點數相同。所以**最長的路不超過最短的兩倍**，高度 $\le2\lg(n+1)$。

?? 選擇 | 紅黑樹從根到葉的最短路有 4 個黑節點、0 個紅節點。最長的路最多幾個節點？

[x] 8
[ ] 16
!! 每條路黑的一樣多（4 個）；紅的最多插在每個黑的後面。
>> 4 黑 + 4 紅 = 8，正好是最短路的兩倍。

插入：新節點**塗紅**（不會破壞規則 5），如果爸爸也是紅的就要修。修正時可能往上重新著色很多次（$O(\lg n)$），但**旋轉最多 2 次**；刪除最多 3 次旋轉。

紅黑樹跟 **2-3-4 樹**（每個節點放 1–3 個鍵）一對一：把黑節點和它的紅孩子合成一個大節點，就是 2-3-4 樹。所以黑高相同 = 2-3-4 樹所有葉子同深度。

[x] AVL 比較矮，搜尋比較快；紅黑刪除時的旋轉比較少
[ ] 紅黑樹比 AVL 矮
[ ] 兩者刪除都最多一次旋轉
!! AVL 大約 $1.44\lg n$，紅黑最多 $2\lg n$。
>> AVL 平衡得比較嚴格，所以矮；但刪除可能要 $O(\lg n)$ 次旋轉，紅黑最多 3 次。

?? 選擇 | 「任何 AVL 樹都可以塗色變成合法的紅黑樹」對嗎？
[x] 對
[ ] 不對
!! 反過來呢？紅黑樹允許的高度差比較大還是小？
>> 對（課本有證明）；反過來不一定，紅黑樹可能有高度差超過 1 的節點。

?? 填空 | 紅黑樹的黑高（從根往下、不含根、含 NIL）是 3。從根到 NIL 的路徑最多有幾個節點（不含 NIL）？

=== ds-bst#5
title: Splay tree、Treap、加欄位的樹
mins: 30
goal: 知道 splay 每次把存取的點轉到根、攤銷 $O(\lg n)$ 但單次可能 $O(n)$；知道 treap 和「多存子樹大小」的用途
---
> [!先記住]
> **Splay tree** 每次碰到一個點，就把它轉到根：單次可能 $O(n)$，攤銷 $O(\lg n)$，而且常用的東西會一直待在上面。在節點裡多存一點資訊（子樹大小、區間最大值），BST 就能做更多事。

```fig
tree
[7 (5)]([3 (3)]([1 (1)],[5 (1)]),[9 (1)])
cap: 括號裡是子樹大小。找第 4 小：左子樹有 3 個，所以根 7 就是第 4 小
```

**Splay tree**：不存高度、不存顏色。**每次存取一個節點，就用旋轉把它轉到根**（三種轉法：zig、zig-zig、zig-zag）。

好處：最近用過的東西就在根附近，再用很快。代價：某一次可能很慢。

?? 選擇 | Splay tree 每次操作的時間是？
[ ] 最壞 $O(\lg n)$
[x] 攤銷 $O(\lg n)$，單次最壞 $O(n)$
[ ] 平均 $O(1)$
!! 它不保證每次都平衡。
>> 樹可能變成一條鏈，某一次存取要走 $n$ 步；但一整串操作平均每次 $O(\lg n)$（用位能法證，位能取 $\sum\lg(\text{子樹大小})$）。

**Treap** = tree + heap。每個節點有一個鍵（照 BST 排：左小右大）和一個**隨機的優先權**（照「爸爸的優先權比孩子大」排）。插入後用旋轉把優先權調好。

結果：形狀就像「照隨機順序插入的 BST」，**期望高度 $O(\lg n)$**，不用任何平衡規則。

?? 選擇 | Treap 為什麼期望很矮？
[x] 隨機的優先權讓樹的形狀等於隨機順序插入的 BST
[ ] 它每次都把節點轉到根
[ ] 它像 AVL 一樣限制高度差
!! 優先權最大的是根，就像「第一個被插入」的節點。
>> 優先權順序就是一個隨機的插入順序，隨機插入的 BST 期望高度 $O(\lg n)$。

**加欄位的樹**：在每個節點多存一點資訊，就能多做一些事，而且旋轉時能 $O(1)$ 更新：
- 存**子樹大小**：可以 $O(\lg n)$ 找「第 $k$ 小」、算「$x$ 排第幾」（order-statistic tree）。
- 存**子樹裡最大的右端點**：可以 $O(\lg n)$ 找重疊的區間（interval tree）。

?? 選擇 | 每個節點存了子樹大小 size。要找第 $k$ 小，在根時 `size(左子樹) = 5`、$k=7$，下一步？
[ ] 往左找第 7 小
[x] 往右找第 $7-5-1=1$ 小
[ ] 根就是答案
!! 左邊有 5 個、根是第 6 小。
>> 第 7 小在右子樹，而且是右子樹裡的第 $7-6=1$ 小。

?? 寫 | 在手寫板寫出：Splay tree、Treap、AVL 各自用什麼方法保持「不會太高」？
== AVL：記高度，高度差超過 1 就旋轉（保證最壞 $O(\lg n)$）。
== Treap：隨機優先權，形狀像隨機插入的 BST（期望 $O(\lg n)$）。
== Splay：每次把存取的點轉到根（攤銷 $O(\lg n)$，單次可能 $O(n)$）。
!! 三個的保證分別是「最壞」「期望」「攤銷」。
>> 考試常問三者保證的種類不同。

@例題 Order-statistic tree：根是 20（size 7），左子樹的根 10（size 3），右子樹的根 30（size 3）。30 的左孩子 25（size 1）、右孩子 40（size 1）。找第 5 小。
@寫 在根：左邊幾個？根是第幾小？ | 左子樹 3 個，根 20 是第 4 小。
@寫 往哪走、找第幾小？ | $5>4$，往右子樹找第 $5-4=1$ 小。
@步 在 30：左子樹 size 1 | 第 1 小 ≤ 1，往左；25 的左邊沒有東西，25 就是第 1 小。
@答 第 5 小是 25。

=== ds-heap#1

goal: 會用陣列索引找爸爸和孩子；會手動做 insert、extract-max、heapify；知道 Build-Heap 為什麼是 $O(n)$
---

> **max-heap**：每個爸爸都 ≥ 自己的小孩，所以最大值一定在根。兄弟之間誰大不管。它是一棵「從左到右填滿」的二元樹，可以直接存在陣列裡。

**Max-heap**（最大堆積）：一棵**完全二元樹**，而且**每個節點都比它的孩子大**（或相等）。所以最大的一定在根。（min-heap 反過來，最小的在根。）

完全二元樹可以直接存在陣列裡，不用指標。從 1 開始編號時：
- 第 $i$ 格的爸爸在 $\lfloor i/2\rfloor$
- 左孩子在 $2i$、右孩子在 $2i+1$

先看影片開頭：用一家公司想堆積，再存成陣列。

>> 第 3 格。第 3 格的孩子是 6 和 7。

（從 0 開始編號的話：爸爸 $\lfloor(i-1)/2\rfloor$、孩子 $2i+1$、$2i+2$。考試會看清楚是哪一種。）

=== ds-heap#2
title: 優先佇列：各種堆積的操作時間比較

**優先佇列**：可以一直放東西進去，每次拿出「最小（或最大）」的那個。操作有：
- Insert：放進去
- Find-min：看最小的
- Extract-min：拿走最小的
- Decrease-key：把某個東西的值改小
- Union：把兩個優先佇列合併

=== ds-heap#3
title: Leftist heap：讓最右邊的路最短，合併只要 O(lg n)
mins: 25
goal: 會算 null path length $s(x)$；知道 leftist 性質讓最右路徑 $\le\lg(n+1)$；會沿最右路徑合併
---
> [!先記住]
> Leftist heap 故意讓右邊那條路最短，合併兩堆只沿著右邊走，$O(\lg n)$。

```fig
tree
[1 (s=2)]([3 (s=1)]([5 (s=1)],),[2 (s=1)])
cap: 括號裡是 s 值（往下走到空位要幾步）。每個點左邊的 s 都 ≥ 右邊，所以最右邊那條路最短
```

二元堆積合併很慢。**Leftist heap** 是一種**不要求完全二元樹**的堆積，專門為了**快速合併**。

定義 $s(x)$：從 $x$ 往下走到「最近的空位置」要幾步（null path length）。空的位置 $s=0$，葉子 $s=1$。

?? 填空 | 一個節點只有左孩子（左孩子是葉子），沒有右孩子。它的 $s$ 是多少？
== 1
!! 往右馬上就碰到空位置。
>> 最近的空位置在右邊，一步就到，$s=1$。

**Leftist 性質**：每個節點都是 $s(\text{左孩子})\ge s(\text{右孩子})$。意思是：**右邊永遠比較「淺」**，樹往左邊長。

結果：**最右邊那條路很短**，長度不超過 $\lfloor\lg(n+1)\rfloor$。（如果最右路徑長 $r$，那上面 $r$ 層都是滿的，至少 $2^r-1$ 個節點。）

?? 選擇 | 為什麼 leftist heap 的最右路徑很短？
[ ] 因為它是完全二元樹
[x] 因為每個節點的右邊都比左邊淺，最右路徑長 $r$ 就代表至少有 $2^r-1$ 個節點
[ ] 因為右孩子一定是葉子
!! $s(\text{根})=r$ 代表什麼？
>> 從根往下 $r$ 層內都沒有空位置，所以這 $r$ 層是滿的。

**合併（meld）**兩棵 leftist heap（min-heap）：
1. 比較兩個根，**小的當新的根**。
2. 把它的**右子樹**跟另一棵**遞迴合併**，結果接回右邊。
3. 如果右邊的 $s$ 變得比左邊大，**左右交換**。

只沿著兩棵的最右路徑走，所以 $O(\lg n)$。Insert＝跟一個單節點的樹合併；Extract-min＝拿掉根、合併左右子樹。

?? 選擇 | 合併兩棵 leftist min-heap，根分別是 3 和 7。新的根是？接下來做什麼？
[x] 3；把 3 的右子樹跟根為 7 的那棵合併
[ ] 7；把 7 的左子樹跟 3 合併
[ ] 3；把 3 的左子樹跟 7 合併
!! 小的當根；合併只走右邊。
>> 新根 3，遞迴合併「3 的右子樹」和「7 那棵」，最後檢查要不要交換左右。

**Skew heap**：不存 $s$，每次合併後**一律**交換左右。單次可能慢，但攤銷 $O(\lg n)$。

?? 填空 | Leftist heap 中，一個節點的左孩子 $s=2$、右孩子 $s=1$。這個節點的 $s$ 是多少？
== 2
!! $s(x)=1+\min(s(\text{左}),s(\text{右}))$。
>> $1+\min(2,1)=2$。

@例題 兩棵 leftist min-heap：A 是根 2、左孩子 5（葉子）、沒有右孩子；B 是單一節點 4。把它們合併。
@寫 比較根，誰當新根？ | 2 < 4，2 當新根。
@寫 2 的右子樹（空）跟 B 合併，結果接到哪？ | 空和 4 合併就是 4，接成 2 的右孩子。
@步 檢查 leftist 性質 | 左孩子 5 的 $s=1$，右孩子 4 的 $s=1$，$1\ge1$，不用交換。
@答 根 2，左孩子 5，右孩子 4。

=== ds-heap#4
title: Binomial heap：跟二進位加法一模一樣
mins: 35
goal: 知道 $B_k$ 的四個性質；看 $n$ 的二進位就知道 binomial heap 有哪些樹；知道 Union 就是二進位加法
---
> [!先記住]
> 兩個二元堆積合併要 $O(n)$。**Leftist heap** 故意讓右邊那條路很短，合併只沿著右邊走，$O(\lg n)$。**Binomial heap** 把 $n$ 寫成二進位，合併就像二進位加法。

```fig
tree
1
---
tree
1(2)
---
tree
1(3(4),2)
---
tree
1(5(7(8),6),3(4),2)
cap: B₀、B₁、B₂、B₃：大小 1、2、4、8，高度 0、1、2、3
```

**Binomial tree** $B_k$ 這樣長：$B_0$ 是一個點；$B_k$ 是**兩棵 $B_{k-1}$**，把其中一棵的根接成另一棵根的孩子。

所以每長一級節點數就加倍：$B_k$ 有 $2^k$ 個節點、高度 $k$。

?? 填空 | $B_3$ 有幾個節點？
== 8
!! 每升一級節點數加倍，$B_0$ 有 1 個。
>> $2^3=8$。

$B_k$ 的四個性質（考試常考）：
- $2^k$ 個節點
- 高度 $k$
- 深度 $i$ 的地方剛好有 $\binom ki$ 個節點（這就是名字裡 binomial 的來源）
- 根有 $k$ 個孩子，由左到右是 $B_{k-1},B_{k-2},\dots,B_0$

?? 選擇 | $B_4$ 在深度 2 有幾個節點？
[ ] 4
[x] 6
[ ] 8
!! 深度 $i$ 有 $\binom ki$ 個。
>> $\binom42=6$。各深度是 1、4、6、4、1，加起來 16 ✓。

**Binomial heap**：一群 binomial tree，**每種大小最多一棵**，每棵都是 min-heap。$n$ 個元素時，有哪些樹就看 **$n$ 的二進位**：第 $k$ 位是 1，就有一棵 $B_k$。

例：$n=13=1101_2$，就是 $B_3$、$B_2$、$B_0$（8+4+1）。最多 $\lfloor\lg n\rfloor+1$ 棵。

?? 選擇 | 有 11 個元素的 binomial heap，由哪些樹組成？
[x] $B_3$、$B_1$、$B_0$
[ ] $B_3$、$B_2$
[ ] $B_2$、$B_2$、$B_1$、$B_0$
!! 11 寫成二進位。
>> $11=1011_2=8+2+1$。每種大小最多一棵，有兩棵一樣大的就不合法。

**Union**（合併兩個 binomial heap）就是**二進位加法**：兩邊都有 $B_k$ 就合成一棵 $B_{k+1}$（根比較大的接到比較小的下面），像「進位」。$O(\lg n)$。

Insert＝跟一個只有 $B_0$ 的 heap 合併——就像計數器加 1，攤銷 $O(1)$（ds-amortized 學過的二進位計數器）。Extract-min：找最小的根（看 $\lg n$ 棵），拿掉它，它的孩子們剛好組成另一個 binomial heap，再 Union 回去。

?? 選擇 | 一個 7 個元素的 binomial heap 再插入 1 個元素，會發生幾次「兩棵合成一棵」？
[ ] 0 次
[ ] 1 次
[x] 3 次
!! $7=111_2$，加 1 會進位幾次？
>> $111+1=1000$：$B_0+B_0\to B_1$、$B_1+B_1\to B_2$、$B_2+B_2\to B_3$，3 次。

@例題 兩個 binomial heap：$H_1$ 有 6 個元素、$H_2$ 有 3 個元素。合併後有哪些樹？過程中合併了幾次？
@寫 各自由哪些樹組成？ | $6=110_2$：$B_2,B_1$。$3=011_2$：$B_1,B_0$。
@寫 像加法一樣從小的位數開始加 | $B_0$：只有 $H_2$ 有，留下。$B_1$：兩邊都有，合成 $B_2$（進位）。$B_2$：$H_1$ 的 $B_2$ 加上進位來的 $B_2$，合成 $B_3$。
@步 檢查 | $6+3=9=1001_2$：$B_3$、$B_0$ ✓。
@答 合併後是 $B_3$ 和 $B_0$，共合併 2 次。

=== ds-heap#5
title: Fibonacci heap：能偷懶就偷懶，攤銷最快
mins: 35
goal: 知道 Fibonacci heap 各操作的攤銷時間；懂 consolidate 和 cascading cut 在做什麼；知道哪些是攤銷界、哪些不是
---
> [!先記住]
> Fibonacci heap 把整理工作一直拖到「真的要拿最小值」才做。所以 insert、合併、decrease-key 都是攤銷 $O(1)$，只有 extract-min 是攤銷 $O(\lg n)$。

```fig
flow: insert、union：丟進根串列，O(1) -> extract-min 時才整理 -> 度數一樣的兩兩合併*
```

**Fibonacci heap** 的想法：**平常能拖就拖，等到非整理不可的時候一次整理**。
- Insert：直接把新節點丟進「根串列」，$O(1)$。
- Union：兩個根串列接起來，$O(1)$。
- Find-min：一直記著最小的根，$O(1)$。

這些都不整理，根串列會越來越長。

?? 選擇 | Fibonacci heap 連續插入 $n$ 個元素之後，根串列有幾棵樹？
[ ] 1 棵
[ ] 大約 $\lg n$ 棵
[x] $n$ 棵
!! Insert 有整理嗎？
>> 每次插入都只丟進根串列，$n$ 個就是 $n$ 棵單節點樹。

**Extract-min** 時才整理（**consolidate**）：拿掉最小的根，把它的孩子也丟進根串列，然後把**度數一樣的樹兩兩合併**，直到每種度數最多一棵。

剛插入 $n$ 個之後的第一次 extract-min，要合併大約 $n$ 次，是 $\Theta(n)$——但這筆帳由前面 $n$ 次便宜的 insert 分攤，所以攤銷 $O(\lg n)$。

?? 選擇 | 「Fibonacci heap 的 extract-min 最壞是 $O(\lg n)$」對嗎？
[ ] 對
[x] 不對
!! 剛插入 $n$ 個元素後的第一次 extract-min 要做多少事？
>> 那一次是 $\Theta(n)$。$O(\lg n)$ 是**攤銷**的界。

**Decrease-key**：把某節點的值改小。如果變得比爸爸小（違反 heap），就把它**剪下來丟進根串列**。為了不讓樹被剪得太稀疏：爸爸如果**已經被剪掉過一個孩子**（有 mark），爸爸也要被剪下來，一路往上（**cascading cut**）。攤銷 $O(1)$。

?? 選擇 | 為什麼需要 cascading cut？
[x] 確保每棵樹不會被剪得太稀疏，度數為 $k$ 的節點底下還是有夠多節點
[ ] 讓 extract-min 變成 $O(1)$
[ ] 讓根串列變短
!! 如果孩子可以被剪光，度數 $k$ 的樹可能只剩很少節點。
>> 每個節點最多失去一個孩子就會被剪，所以度數 $k$ 的節點底下至少 $F_{k+2}$ 個節點（費氏數），最大度數只有 $O(\lg n)$——名字就是這樣來的。

攤銷分析用位能 $\Phi=$（根的數量）$+2\times$（有 mark 的節點數）：插入多一個根，存 1 元；consolidate 用這些存款付合併的錢。

| 操作 | 攤銷時間 |
|---|---|
| Insert、Union、Find-min | $O(1)$ |
| Decrease-key | $O(1)$ |
| Extract-min、Delete | $O(\lg n)$ |

?? 選擇 | 哪一個操作，Fibonacci heap 比二元堆積明顯快？
[x] Decrease-key（攤銷 $O(1)$ 對 $O(\lg n)$）
[ ] Extract-min
[ ] Find-min
!! 對照兩種的表格。
>> Decrease-key 攤銷 $O(1)$。之後最短路徑、最小生成樹在邊很多的圖上，會呼叫很多次 decrease-key，用 Fibonacci heap 會快。

?? 填空 | Fibonacci heap 的位能是 $\Phi=t+2m$（$t$ 根數、$m$ 被標記的節點數）。有 5 棵樹、3 個標記，$\Phi$ 是多少？
== 11
!! 代進去。
>> $5+2\times3=11$。

@例題 Fibonacci heap 根串列裡有度數 0、0、1、0、2 的五棵樹（度數＝根有幾個孩子）。consolidate 之後還剩幾棵？各是什麼度數？
@寫 先把度數 0 的兩兩合併 | 三棵度數 0：前兩棵合成一棵度數 1，剩一棵度數 0。
@寫 度數 1 現在有幾棵？合併 | 原本的一棵加上剛合成的一棵，兩棵度數 1 合成一棵度數 2。
@步 度數 2 | 原本一棵、剛合成一棵，再合成一棵度數 3。
@答 剩 2 棵：度數 0 和度數 3。

=== ds-sort#1
title: 排序總表：插入、選擇、合併、快速、堆積排序
mins: 40
goal: 會手動跑插入、選擇、合併、快速、堆積排序；記得每一種的時間、額外空間、穩不穩定
---
> [!先記住]
> **穩定**＝一樣大的東西，排完以後原本的先後順序不變。合併、插入、泡沫、計數、基數是穩定的；快速、堆積、選擇不穩定。

```fig
array
row 排序前: 2a 1 2b
row 穩定: 1 2a* 2b*
row 不穩定: 1 2b! 2a!
cap: 兩個 2 一樣大。穩定的排序保證 2a 還在 2b 前面
```

```fig
array
row 開始: 5 2 4 1
row 插 2: 2* 5 4 1
row 插 4: 2 4* 5 1
row 插 1: 1* 2 4 5
cap: 左邊是已經排好的部分，每次把下一張插進去
```

排序是考試必考。先認識五種基本的比較排序（都是「兩兩比大小」決定順序）：

- **插入排序**：像整理撲克牌，每拿一張就往前插到對的位置。
- **選擇排序**：每輪找出剩下最小的，跟最前面交換。
- **合併排序**：切兩半、各自排好、再合併。$T(n)=2T(n/2)+n=\Theta(n\lg n)$。

?? 選擇 | 對 `[5, 2, 4, 1]` 做插入排序，第一輪（處理 2）之後陣列變成？
[x] `[2, 5, 4, 1]`
[ ] `[1, 2, 4, 5]`
[ ] `[2, 4, 5, 1]`
!! 只看前兩個：把 2 插到 5 前面。
>> 插入排序每輪讓前 $k$ 個排好。第一輪後前兩個是 2、5。

插入排序最好的情況（已經排好）只要 $n-1$ 次比較；最壞（完全倒過來）$\Theta(n^2)$。更精確：時間 $=\Theta(n+I)$，$I$ 是**逆序對**的數量（前面比後面大的配對）。

- **快速排序**（quicksort）：挑一個 **pivot**，把比它小的放左邊、大的放右邊（叫 partition），兩邊再遞迴。平均 $\Theta(n\lg n)$，最壞 $\Theta(n^2)$。
- **堆積排序**：先 Build-Heap（$O(n)$），再做 $n$ 次 extract-max，每次 $O(\lg n)$，總共 $\Theta(n\lg n)$，不需要額外陣列。

?? 填空 | `[3, 1, 2]` 有幾個逆序對？
== 2
!! 一對一對看：(3,1)、(3,2)、(1,2)，哪些是前面比後面大？
>> (3,1) 和 (3,2) 是逆序對，共 2 個。

**穩定**：值一樣的兩個元素，排完後**前後順序不變**。例如照分數排序時，同分的人保持原本的學號順序。
- 穩定：插入、泡沫、合併
- 不穩定：選擇、快速、堆積

**原地（in-place）**：只用常數額外空間。合併排序（陣列版）要多開 $n$ 格，不是原地；堆積排序是原地。

?? 選擇 | 哪一個排序是穩定的？
[x] 合併排序
[ ] 堆積排序
[ ] 選擇排序
!! 合併兩半時，兩邊一樣大先拿哪一邊？
>> 合併排序遇到相等時先拿左邊的，所以保持原順序。堆積和選擇都會把相同的值換來換去。

總表（考試要背的那張）：

| 排序 | 平均 | 最壞 | 額外空間 | 穩定 |
|---|---|---|---|---|
| 插入 | $n^2$ | $n^2$ | $1$ | ✓ |
| 選擇 | $n^2$ | $n^2$ | $1$ | ✗ |
| 合併 | $n\lg n$ | $n\lg n$ | $n$ | ✓ |
| 快速 | $n\lg n$ | $n^2$ | $\lg n$ | ✗ |
| 堆積 | $n\lg n$ | $n\lg n$ | $1$ | ✗ |

?? 選擇 | 資料「幾乎已經排好」（只有少數幾個位置錯），哪一個最快？
[x] 插入排序
[ ] 選擇排序

>> 逆序對很少時插入排序接近 $O(n)$；選擇排序不管怎樣都 $\Theta(n^2)$；堆積排序一樣 $\Theta(n\lg n)$。

?? 選擇 | 「最壞情況也保證 $O(n\lg n)$，而且只用常數額外空間」的是？

>> 堆積排序兩個都符合，代價是不穩定。

=== ds-sort#2
title: 比較排序的下界：為什麼不可能比 n lg n 快
mins: 30
goal: 會用決策樹說明比較排序最壞至少 $\lg n!=\Theta(n\lg n)$ 次比較；知道「找最大最小」等常考的下界
---
> [!先記住]
> 只能問「誰比較大」的排序，每問一次最多把可能性砍一半；$n$ 個數有 $n!$ 種排法，所以至少要問 $\lg(n!)\approx n\lg n$ 次。

```fig
tree
[a<b?]([b<c?]([a b c],[a<c?]([a c b],[c a b])),[a<c?]([b a c],[b<c?]([b c a],[c b a])))
cap: 3 個數的決策樹：6 種答案各占一片葉子，最深要比 3 次
```

上一節的比較排序最快都是 $n\lg n$。是大家不夠聰明，還是根本不可能更快？答案是**不可能**——只要是「靠比大小」的排序。

先看影片：三個人排身高，只能兩兩比，最少要問幾次。

@影片 ds-sort 0-69.2

**決策樹**：把排序過程畫成一棵二元樹，每個內部節點是一次比較（$a_i<a_j$？），往左往右是兩種結果，每片葉子是一種最後的排列。

$n$ 個不同的數有 $n!$ 種排列，每一種都要有一片葉子對應，所以葉子 $\ge n!$。

?? 填空 | 排序 3 個不同的數，決策樹至少有幾片葉子？
== 6
!! 3 個數有幾種排列？
>> $3!=6$ 種，每種都要能被分辨出來。

高度 $h$ 的二元樹最多 $2^h$ 片葉子，所以
$$2^h\ge n!\quad\Rightarrow\quad h\ge\lg(n!)$$
而 $\lg(n!)=\Theta(n\lg n)$（漸近符號那一節學過）。樹的高度＝最壞情況的比較次數。

?? 選擇 | 排序 4 個不同的數，最壞情況至少要比較幾次？
[ ] 4
[x] 5
[ ] 6
!! $4!=24$，$2^h\ge24$，$h$ 最小是多少？
>> $2^4=16<24\le32=2^5$，所以至少 5 次。

再看影片：人多的時候要問幾次，還有 $\log_2(n!)$ 到底多大。

@影片 ds-sort 69.3-145.7

注意：這是**最壞**情況的下界。**平均**也一樣是 $\Omega(n\lg n)$（葉子的平均深度至少 $\lg n!$）。但**最好**情況可以很快：插入排序對已經排好的只要 $n-1$ 次。

計數排序、基數排序**不靠比大小**（直接看數值），所以不受這個下界限制，下一節會學。

?? 選擇 | 「任何排序演算法最壞都至少要 $\Theta(n\lg n)$ 時間」對嗎？
[ ] 對
[x] 不對
!! 這個下界的前提是什麼？
>> 只對「比較排序」成立。計數排序在值的範圍不大時是 $O(n)$。

其他常考的下界：
- **同時找最大和最小**：兩兩一組，組內比一次，小的跟目前最小比、大的跟目前最大比，共 $\lceil 3n/2\rceil-2$ 次，比分開找的 $2n-2$ 少。
- **找第二小**：像錦標賽，冠軍打敗過的 $\lceil\lg n\rceil$ 個人裡找最小，共 $n+\lceil\lg n\rceil-2$ 次。

?? 填空 | 10 個數，用「兩兩一組」的方法同時找最大和最小，要比較幾次？
== 13
!! $\lceil 3n/2\rceil-2$，$n=10$。
>> $15-2=13$ 次（分開找要 $9+9=18$ 次）。

@例題 證明：任何比較排序在最壞情況下至少要 $\Omega(n\lg n)$ 次比較。
@寫 用決策樹說明葉子數 | 每一種輸入的排列都要走到不同的葉子，$n$ 個不同的數有 $n!$ 種排列，所以葉子 $\ge n!$。
@寫 寫出高度的不等式 | 高度 $h$ 的二元樹最多 $2^h$ 片葉子：$2^h\ge n!$，$h\ge\lg n!$。
@步 估 $\lg n!$ | $n!\ge(n/2)^{n/2}$（後一半每個因數都 $\ge n/2$），所以 $\lg n!\ge\frac n2\lg\frac n2=\Omega(n\lg n)$。
@答 最壞比較次數＝樹高 $\ge\lg n!=\Omega(n\lg n)$。

=== ds-sort#3
title: Quicksort：partition、最壞與期望
mins: 40
goal: 會手動做 Lomuto partition；知道最壞 $\Theta(n^2)$ 的成因；會用「兩個元素被比較的機率」算期望比較次數
---
> [!先記住]
> **合併排序**：切兩半、各自排好、再合併，永遠 $n\lg n$。**快速排序**：挑一個基準（pivot），小的放左、大的放右，再各自排；平均 $n\lg n$，但每次都挑到最大或最小時會變 $n^2$。

```fig
tree
[5 2 4 1]([5 2]([5],[2]),[4 1]([4],[1]))
---
tree
[1 2 4 5]([2 5]([5],[2]),[1 4]([4],[1]))
cap: 左：一路切到只剩一個。右：由下往上合併。共 lg n 層，每層合併總共 n 個 → n lg n
```

**Partition**（Lomuto 版，CLRS 用的）：以最後一個元素當 pivot $x$，由左往右掃，維持「左段都 $\le x$、中段都 $>x$」，掃完把 pivot 換到兩段中間。

```
x = A[r]; i = p - 1;
for j = p .. r-1:
    if A[j] <= x: i++, swap(A[i], A[j])
swap(A[i+1], A[r])      // pivot 到位，回傳 i+1
```

?? 選擇 | 對 `[3, 8, 2, 5, 4]` 用最後一個（4）當 pivot 做 partition，結束後陣列是？
[x] `[3, 2, 4, 5, 8]`
[ ] `[2, 3, 4, 5, 8]`
[ ] `[3, 2, 5, 8, 4]`
!! 掃過 3、8、2、5：哪些 ≤ 4 要換到前面？最後 pivot 換到中間。
>> 3、2 ≤ 4，換到前面：`[3,2,8,5,4]`；再把 4 換到第 3 格：`[3,2,4,5,8]`。左右兩邊還沒排好，要遞迴。

**最壞情況**：每次 pivot 都是最大或最小，切成 0 和 $n-1$。$T(n)=T(n-1)+\Theta(n)=\Theta(n^2)$。用最後一個當 pivot 時，**已經排好的陣列**就是最壞情況。

只要每次至少切出**固定比例**（就算是 1:99），遞迴樹高度還是 $O(\lg n)$，每層 $O(n)$，總共 $\Theta(n\lg n)$。

?? 選擇 | quicksort 每次都切成 1:9，時間是？
[ ] $\Theta(n^2)$
[x] $\Theta(n\lg n)$
[ ] $\Theta(n)$
!! 遞迴樹每層加起來多少？最深幾層？
>> 每層加起來 $\le n$，最深 $\log_{10/9}n=O(\lg n)$ 層，所以 $\Theta(n\lg n)$。

**隨機選 pivot**（Randomized quicksort）：每次隨機挑 pivot，最壞情況就不會被特定輸入觸發，期望 $\Theta(n\lg n)$。

**期望比較次數**的算法（用期望值可以相加）：把排好後的元素叫 $z_1<z_2<\cdots<z_n$。$z_i$ 和 $z_j$ 會被比較，**當且僅當** $z_i,\dots,z_j$ 這 $j-i+1$ 個裡，第一個被挑為 pivot 的是 $z_i$ 或 $z_j$（否則中間某個先當 pivot，就把它們分開了）。機率是 $\frac{2}{j-i+1}$。

?? 填空 | $z_3$ 和 $z_7$ 被比較的機率是多少？（寫分數）
== 2/5
== 0.4
!! $z_3..z_7$ 共幾個？其中兩個是 $z_3$、$z_7$。
>> 共 5 個，第一個被挑中的是 $z_3$ 或 $z_7$ 的機率 $\frac25$。

把所有配對的機率加起來：
$$E[\text{比較次數}]=\sum_{i<j}\frac{2}{j-i+1}\approx2n\ln n\approx1.39\,n\lg n$$

?? 選擇 | 相鄰的 $z_i$ 和 $z_{i+1}$ 被比較的機率是？
[ ] $\frac12$
[x] 1
[ ] $\frac2n$
!! $j-i+1=2$。
>> $\frac22=1$：相鄰的兩個一定會被比到（中間沒有別人能把它們分開）。

@例題 用最後一個元素當 pivot，對 `[1, 2, 3, 4, 5]` 做 quicksort。總共比較幾次？為什麼這是最壞情況？
@寫 第一次 partition（pivot 5）比較幾次？切成什麼？ | 跟 1、2、3、4 各比一次，共 4 次；切成 `[1,2,3,4]` 和空的。
@寫 接下來每一層呢？ | pivot 4：3 次；pivot 3：2 次；pivot 2：1 次。
@步 加總並說明 | $4+3+2+1=10=\frac{n(n-1)}2$。每次 pivot 都是最大的，切成 $n-1$ 和 0，遞迴深度 $n$。
@答 10 次，是 $\Theta(n^2)$ 的最壞情況；隨機選 pivot 可以避免。

=== ds-sort#4
title: 線性時間排序：計數、基數、桶排序
mins: 35
goal: 會手動做計數排序（由後往前放）；知道基數排序每一位要用穩定的排序；知道桶排序要均勻分布
---
> [!先記住]
> 數值範圍不大時，可以直接把數值當成「格子編號」：**計數排序** $O(n+k)$。很多位數的數字，就從個位數開始一位一位用計數排序：**基數排序**。

```fig
array
row 原本: 170 45 75 90 802 24 2 66
row 個位排: 170 90 802 2 24 45 75 66
row 十位排: 802 2 24 45 66 170 75 90
row 百位排: 2 24 45 66 75 90 170 802*
cap: 基數排序（LSD）：從最低位開始，每一位用穩定的排序。每輪都要穩定，前面排好的才不會被打亂
```

不比大小，直接**看數值**，就能打破 $n\lg n$ 的下界。代價是要對資料有假設（例如都是 0 到 $k$ 的整數）。

**計數排序**（值在 $0..k$）：
1. `C[x]` 數每個值出現幾次。
2. 前綴和：`C[x]` 變成「$\le x$ 的有幾個」，也就是 $x$ 最後一個該放的位置。
3. **由後往前**掃原陣列，把 `A[j]` 放到 `B[C[A[j]]]`，然後 `C[A[j]]--`。

時間 $\Theta(n+k)$。由後往前放，是為了**穩定**。

?? 填空 | `A = [2, 0, 2, 1]`，做完第 1 步（計數）後 `C[2]` 是多少？
== 2
!! 2 出現幾次？
>> 2 出現 2 次。前綴和之後 `C = [1, 2, 4]`。

?? 選擇 | 計數排序最後一步為什麼要「由後往前」掃？
[x] 讓相同的值保持原本的前後順序（穩定）
[ ] 比較快
[ ] 不然會放錯位置
!! 同一個值的最後一個位置是 `C[x]`，先放的是誰？
>> 由後往前掃，同值裡最後出現的先放到最後的位置，順序就不會顛倒。

**基數排序**（LSD）：從**最低位**開始，每一位用一次穩定的排序（通常是計數排序），一位一位排到最高位。

為什麼要穩定？排高位時，高位一樣的要保持低位排好的順序。

?? 選擇 | 對 `[329, 457, 657, 839]` 做基數排序，第一輪（看個位數）之後是？
[x] `[457, 657, 329, 839]`
[ ] `[329, 457, 657, 839]`
[ ] `[839, 329, 457, 657]`
!! 個位數：9、7、7、9。穩定：同樣是 7 的保持原順序。
>> 個位 7 的 457、657（原順序）在前，9 的 329、839 在後。

時間：$d$ 位數、每位 $0..k$：$\Theta(d(n+k))$。$d$ 和 $k$ 是常數時就是 $\Theta(n)$。

**桶排序**：輸入是 $[0,1)$ 之間**均勻分布**的實數。分成 $n$ 個桶，每個數丟進對應的桶，每個桶用插入排序，再接起來。期望 $\Theta(n)$；如果全部擠在同一桶，就變 $\Theta(n^2)$。

?? 選擇 | 下面哪一句對？
[ ] 基數排序是比較排序
[x] 基數排序每一位用的排序必須穩定
[ ] 計數排序不能排負數
!! 負數可以怎麼處理？
>> 基數排序不靠比較；計數排序遇到負數，全部加一個常數平移就好。

@例題 用計數排序排 `A = [3, 1, 3, 0, 2]`（值在 0..3），寫出 C 的變化和最後的 B。
@寫 計數 | `C = [1, 1, 1, 2]`（0 有 1 個、1 有 1 個、2 有 1 個、3 有 2 個）。
@寫 前綴和 | `C = [1, 2, 3, 5]`。
@步 由後往前放 | A[5]=2 → B[3]，C[2]=2；A[4]=0 → B[1]；A[3]=3 → B[5]，C[3]=4；A[2]=1 → B[2]；A[1]=3 → B[4]。
@答 `B = [0, 1, 2, 3, 3]`，兩個 3 保持原順序（原本第 1 個 3 在 B[4]、第 3 個 3 在 B[5]）。

=== ds-hash#1
title: 雜湊函數：把鍵變成格子編號
mins: 35
goal: 知道雜湊表為什麼平均 $O(1)$；會用除法法、乘法法；知道 universal hashing 在保證什麼
---
> [!先記住]
> **雜湊**：用一個公式 $h(k)$ 把鍵直接算成表格的位置，一步就到。兩個鍵算出同一格叫**碰撞**；好的公式讓碰撞平均分散。

```fig
array
row k mod 7: _ _ _ 10 _ _ _
idx: 0 1 2 3 4 5 6
---
array
row 也想進 3 號: 17! 24!
cap: 10、17、24 除以 7 都餘 3：三個鍵搶同一格，這就是碰撞
```

想用 $O(1)$ 找到一個東西：開一個 $m$ 格的陣列，用**雜湊函數** $h$ 把鍵 $k$ 變成格子編號 $h(k)\in\{0,\dots,m-1\}$，直接跳過去。

兩個不同的鍵算出同一格，叫**碰撞**。鍵比格子多的時候，碰撞一定會發生（鴿籠原理）。

?? 選擇 | 為什麼雜湊表一定要處理碰撞？
[x] 可能的鍵通常遠多於格子數，一定有不同的鍵落在同一格
[ ] 因為雜湊函數寫錯了
[ ] 只有鍵重複時才會碰撞
!! 學號有幾百萬種可能，表只有 1000 格。
>> 鴿籠原理：鍵的種類比格子多，就一定有兩個鍵在同一格。下兩節學兩種解決方法。

**除法法**：$h(k)=k\bmod m$。
- $m$ 取**不接近 2 的次方的質數**比較好。
- $m=2^p$ 很糟：$k\bmod2^p$ 只看 $k$ 的最低 $p$ 個位元，高位元完全沒用到。

?? 填空 | $m=13$，$h(k)=k\bmod13$。$h(40)$ 是多少？
== 1
!! $40=3\times13+1$。
>> 放在第 1 格。

?? 選擇 | 鍵都是偶數，$m=8$，用 $k\bmod m$。會發生什麼事？
[x] 只會用到 0、2、4、6 四格，碰撞變多
[ ] 均勻分到 8 格
[ ] 全部都在 0 格
!! 偶數除以 8 的餘數可能是哪些？
>> 偶數 mod 8 一定是偶數，一半的格子永遠空著。$m$ 取質數就不會這樣。

**乘法法**：$h(k)=\lfloor m\cdot(kA\bmod1)\rfloor$，$0<A<1$。（$kA\bmod1$ 是 $kA$ 的小數部分。）好處是 $m$ 可以取 $2^p$；Knuth 建議 $A\approx0.618$。

**Universal hashing**：如果雜湊函數固定，壞人可以故意挑全部撞在一起的鍵。解法是從一**族**函數裡**隨機挑一個**，保證**任兩個不同的鍵碰撞的機率 $\le\frac1m$**。常用的一族：
$$h_{a,b}(k)=((ak+b)\bmod p)\bmod m$$
$p$ 是比所有鍵大的質數，$a,b$ 隨機選。

?? 選擇 | universal hashing 保證的是？
[ ] 永遠不會碰撞
[x] 不管輸入怎麼挑，任兩個鍵碰撞的機率都 $\le1/m$
[ ] 搜尋最壞 $O(1)$
!! 隨機性來自哪裡：輸入，還是挑函數？
>> 隨機的是函數，所以就算輸入是故意設計的，期望表現還是好。

?? 寫 | 在手寫板算 $h(k)=k\bmod 7$，把 10、24、31、17 放進 7 格的表，標出哪些碰撞。
== 10→3、24→3、31→3、17→3：全部在第 3 格！
!! 一個一個算餘數。
>> 這組鍵剛好都 $\equiv3\pmod7$，固定的雜湊函數遇到這種輸入就很慘——這就是 universal hashing 要解決的問題。

@例題 用乘法法 $h(k)=\lfloor m(kA\bmod1)\rfloor$，$m=8$、$A=0.625$。算 $h(3)$ 和 $h(5)$。
@寫 算 $h(3)$ | $3\times0.625=1.875$，小數部分 $0.875$，$8\times0.875=7$，$h(3)=7$。
@寫 算 $h(5)$ | $5\times0.625=3.125$，小數部分 $0.125$，$8\times0.125=1$，$h(5)=1$。
@步 觀察 | 3 和 5 很接近，卻被分到差很遠的格子：乘法法把鍵「打散」。
@答 $h(3)=7$、$h(5)=1$。

title: 進階雜湊：完美雜湊、Cuckoo、Bloom filter
mins: 30
goal: 知道完美雜湊和 Cuckoo 的最壞 $O(1)$ 搜尋；會說明 Bloom filter 只會誤判「有」；知道生日問題的碰撞量級
---
> [!先記住]
> **完美雜湊**和 **Cuckoo hashing** 讓「找」最壞也是 $O(1)$。**Bloom filter** 用很少的空間回答「在不在」：說「不在」一定對，說「在」可能錯。

```fig

row 位元: 0 1* 0 1* 0 1* 0

```

前面的雜湊表搜尋是**期望** $O(1)$。有些方法能做到**最壞** $O(1)$：

**完美雜湊**（FKS，鍵的集合固定不變時）：兩層。第一層把 $n$ 個鍵分到 $n$ 格；第 $j$ 格有 $n_j$ 個鍵，就給它開一個 $n_j^2$ 格的第二層表——夠大，可以選一個完全不碰撞的函數。期望總空間 $O(n)$，搜尋**最壞** 2 次。

?? 選擇 | 完美雜湊的第二層，為什麼開 $n_j^2$ 格？
[x] 格子數是鍵數的平方時，隨機挑函數完全不碰撞的機率至少一半
[ ] 這樣比較省空間
[ ] 因為 $n_j$ 一定是 2 的次方
!! 生日問題：$n_j$ 個鍵、$n_j^2$ 格，碰撞的期望對數是多少？
>> 期望碰撞對數 $\binom{n_j}2\cdot\frac{1}{n_j^2}<\frac12$，所以多試幾次就找得到不碰撞的函數。

**生日問題**：$n$ 個鍵丟進 $m$ 格，$n$ 大約 $1.18\sqrt m$ 時，有碰撞的機率就到一半。365 天，23 個人就有一半機率有人同一天生日。

?? 填空 | 表有 10000 格，大約放幾個鍵，有碰撞的機率就到一半？（取整數）
== 118
== 120
!! $1.18\sqrt m$。
>> $1.18\times100=118$。碰撞比直覺早很多出現。

**Cuckoo hashing**：兩個表、兩個雜湊函數，每個鍵**只可能**在 $T_1[h_1(k)]$ 或 $T_2[h_2(k)]$。搜尋最多看 2 格：最壞 $O(1)$。插入時如果被佔了，就把佔位者**踢到它的另一個位置**，可能連鎖踢下去。

**Bloom filter**：用 $m$ 個位元和 $k$ 個雜湊函數記錄「某個東西有沒有出現過」。
- 加入 $x$：把 $h_1(x),\dots,h_k(x)$ 這 $k$ 位設成 1
- 查詢 $x$：$k$ 位都是 1 就說「可能有」，有一位是 0 就說「一定沒有」

**只會誤判成「有」（偽陽性），不會誤判成「沒有」**。很省空間，但一般版本不能刪除。

?? 選擇 | Bloom filter 回答「沒有」的時候，這個答案？
[x] 一定正確
[ ] 可能是錯的
[ ] 要再查一次才知道
!! 如果 $x$ 真的加入過，它的 $k$ 個位元會是什麼？
>> 加入過的東西，$k$ 位一定都是 1；有一位是 0 就證明沒加入過。說「有」才可能是別人湊巧把那些位都設成 1。

?? 寫 | 在手寫板寫出：為什麼一般的 Bloom filter 不能刪除？
== 把 $x$ 的 $k$ 個位元清成 0，可能也清掉了別的元素用到的位元，之後查那些元素會得到「沒有」——變成偽陰性。
!! 不同元素可能共用同一個位元。
>> 要刪除就得改用「計數版」（每格存次數，而不是 0/1）。

@例題 Bloom filter 有 10 個位元（編號 0–9），$h_1(x)=x\bmod10$、$h_2(x)=(3x)\bmod10$。加入 4 和 7 之後，查詢 8 和 2 的結果？
@寫 加入 4、7 後，哪些位元是 1？ | 4：$h_1=4$、$h_2=12\bmod10=2$；7：$h_1=7$、$h_2=21\bmod10=1$。位元 1、2、4、7 是 1。
@寫 查詢 8 | $h_1=8$、$h_2=24\bmod10=4$。位元 8 是 0 → 一定沒有。
@步 查詢 2 | $h_1=2$、$h_2=6$。位元 6 是 0 → 一定沒有。（如果剛好兩位都是 1，就會回答「可能有」——偽陽性。）

=== ds-graph#2
title: BFS：一圈一圈往外，找最短距離
mins: 35
goal: 會手動跑 BFS、寫出每個點的距離；知道 BFS 在無權圖找最短路徑、時間 $O(V+E)$；會用 BFS 判斷二分圖

> [!先記住]
> **BFS（廣度優先搜尋）**：從起點出發，先走完距離 1 的點，再走距離 2 的點……用一個**佇列**。第一次碰到某個點時走的路，就是邊數最少的路。$O(V+E)$。

```fig
graph
nodes: s*@0,1 a@1,0 b@1,2 c@2,0 d@2,2 e@3,1
edges: s-a s-b a-c b-d c-e d-e
cap: 從 s 開始：距離 1 是 a、b；距離 2 是 c、d；距離 3 是 e
```

**BFS**（廣度優先搜尋）：從起點 $s$ 出發，**先拜訪所有距離 1 的點，再拜訪距離 2 的**……像水波一圈一圈往外。

用一個**佇列**：
1. $s$ 放進佇列，距離 0
2. 拿出佇列最前面的點 $u$，把它**還沒拜訪過**的鄰居都設成「距離 $u$+1」，放進佇列
3. 重複到佇列空

?? 選擇 | 圖：s–a、s–b、a–c、b–c、c–d。從 s 做 BFS，d 的距離是？
[ ] 2
[x] 3
[ ] 4
!! 一層一層：s（0）→ a、b（1）→ c（2）→ ?
>> d 只跟 c 相鄰，距離 3。

BFS 第一次碰到一個點時，就是**最短距離**（邊都一樣長的話）。所以 BFS 能在**無權圖**找最短路徑：記住每個點是誰發現的（父親），沿著父親往回走就是路徑。

時間：每個點進出佇列一次、每條邊看一兩次：$O(V+E)$。

== s,a,b,c,d
== s, a, b, c, d
!! 先處理 s，再依佇列順序處理 a、b。
>> s → a、b → 處理 a：c → 處理 b：c 已拜訪過，加 d。順序 s、a、b、c、d。

BFS **不能**直接找有權重的最短路徑（邊長不一樣時，走比較少步不代表比較短）——那是之後最短路徑章的事。

**判斷二分圖**：BFS 時把每一層交替塗兩色（距離偶數一色、奇數一色）。如果發現某條邊兩端**同色**（同一層），就有奇環，不是二分圖。

[x] 有奇環，不是二分圖
[ ] 是二分圖
[ ] BFS 做錯了
!! 從 $s$ 到兩點各走 2 步，再加上這條邊，形成多長的環？
>> 2+2+1=5，奇環。


```
        標記 u 黑色，u.f = ++time
```

```fig

nodes: a*@0,0 b*@1,0 c*@0.5,1 d+@2,0 e+@3,0
edges: a>b b>c c>a b>d d>e e>d

```

**Kosaraju 演算法**：
1. 對 $G$ 做 DFS，記下每點的完成時間 $f$
2. 把所有邊反過來，得到 $G^T$
3. 照 $f$ **由大到小**的順序，在 $G^T$ 上做 DFS；**每一棵 DFS 樹就是一個 SCC**

?? 排序 | Kosaraju 的步驟
- 對原圖做 DFS，算出完成時間
- 把所有邊反向
- 照完成時間由大到小，在反向圖上做 DFS
- 每一棵 DFS 樹是一個 SCC
>> 兩次 DFS 加一次轉置。

為什麼要反向？完成時間最大的點，在「最上游」的 SCC 裡。邊反過來之後，從它出發走不出它自己的 SCC（原本往下游的邊都變成往上游、而上游沒有了）。

>> 互相到得了的關係，反向後還是成立，所以 SCC 相同。

=== ds-unionfind#1
title: Union-Find：誰跟誰同一群
mins: 35
goal: 會用 MAKE-SET、UNION、FIND-SET；比較串列和森林兩種表示；知道 union by rank、路徑壓縮各自的效果
---
> [!先記住]
> **Union-Find** 管理一堆「互不重疊的群」。每一群選一個**代表**（老大）。想知道兩個人是不是同一群，就問他們的老大是不是同一個人。

```fig
tree up
1*(2,3(4(5)))
---
tree up
1*(2,3,4,5)
cap: 箭頭指向「我的上司」。FIND(5) 要走 5 → 4 → 3 → 1；路徑壓縮後，路上的 5、4、3 全部直接指向 1
```

**不相交集合**（Union-Find）：一群東西分成好幾組，要支援三個操作：
- **MAKE-SET**$(x)$：$x$ 自己一組
- **FIND-SET**$(x)$：$x$ 在哪一組？（回傳那組的**代表**）
- **UNION**$(x,y)$：把 $x$、$y$ 所在的兩組合併

判斷「$x$、$y$ 是不是同一組」＝比 FIND-SET$(x)$ 和 FIND-SET$(y)$ 一不一樣。

?? 選擇 | 一開始 1、2、3、4 各自一組。做 UNION(1,2)、UNION(3,4)、UNION(2,3) 之後，有幾組？
[x] 1
[ ] 2
[ ] 3
!! 一步一步合併。
>> {1,2}、{3,4}，再把 2 和 3 所在的組合併：{1,2,3,4}。

**森林表示法**：每一組是一棵樹，**根是代表**，每個點只存「爸爸是誰」。
- FIND：一路往上走到根
- UNION：把一棵樹的根，接到另一棵樹的根下面

問題：隨便接，樹可能長成一條鏈，FIND 要 $O(n)$。

?? 選擇 | 依序 UNION(1,2)、UNION(1,3)、UNION(1,4)……每次都把「大的那組的根」接到「新來的那個點」下面。樹會變成？
[x] 一條長鏈，FIND 很慢
[ ] 很矮的樹
!! 每次都把整棵樹接到一個點下面，高度會怎樣？
>> 每次高度加 1，變成一條鏈。所以要用「矮的接到高的下面」。

兩個改善：
- **union by rank**：每個根記一個 rank（大約是高度），**rank 小的根接到 rank 大的根下面**。這樣高度最多 $\lg n$。
- **路徑壓縮**：FIND 時，把**路上每個點都直接接到根**。下次找就一步到。

兩個一起用：$m$ 次操作總共 $O(m\,\alpha(n))$，$\alpha(n)$ 長得極慢（實際上 $\le4$）。

?? 選擇 | 路徑壓縮在什麼時候做？
[x] FIND 的時候
[ ] UNION 的時候
[ ] MAKE-SET 的時候
!! 「路徑」是指誰的路徑？
>> FIND 往上走的那條路，走完順便把它們都接到根。

?? 寫 | 在手寫板畫：1 是根，2 的爸爸是 1，3 的爸爸是 2，4 的爸爸是 3。做 FIND(4) 並路徑壓縮後，樹長什麼樣子？
== FIND(4) 走 4→3→2→1，根是 1。
== 壓縮後 2、3、4 的爸爸都是 1（一棵高度 1 的樹）。
!! 路上經過的每個點都直接指向根。
>> 下次 FIND(4)、FIND(3) 都一步就到。

**串列表示法**（另一種）：每組一條鏈結串列，每個元素存「代表是誰」。FIND $O(1)$；但 UNION 要把一整條的代表指標都改掉。改良版「短的接到長的後面」：每個元素的代表指標最多被改 $\lg n$ 次（每次被改，所在的組至少變兩倍大），總共 $O(m+n\lg n)$。

@例題 用 union by rank（rank 一樣時，第二個接到第一個下面，並把第一個的 rank 加 1）：MAKE-SET 1–4，然後 UNION(1,2)、UNION(3,4)、UNION(1,3)。畫出最後的樹和每個根的 rank。
@寫 UNION(1,2)、UNION(3,4) 之後 | 2 接到 1 下，1 的 rank 變 1；4 接到 3 下，3 的 rank 變 1。
@寫 UNION(1,3)：兩個根 rank 都是 1 | 3 接到 1 下面，1 的 rank 變 2。
@步 畫出結果 | 1 是根（rank 2），孩子 2 和 3；3 的孩子 4。高度 2 ≤ $\lg 4$ ✓。
@答 根 1（rank 2）；1 → {2, 3}；3 → {4}。

=== ds-unionfind#2
title: Rank 的性質與 α(n)：為什麼幾乎是常數
mins: 30
goal: 知道 rank 沿路嚴格遞增、rank $r$ 的子樹至少 $2^r$ 點；知道 $\alpha(n)\le4$ 但不是 $O(1)$；知道是攤銷界
---
> [!先記住]
> rank 為 $r$ 的根，它的樹至少有 $2^r$ 個點。所以 rank 最大 $\lfloor\lg n\rfloor$。$\alpha(n)$ 長得極慢，對宇宙裡能想像的任何 $n$ 都 $\le4$，但理論上它不是常數。

```fig
bars
bar n = 3: 1 α = 1
bar n = 7: 2 α = 2
bar n = 2047: 3 α = 3
bar n ≤ 10⁸⁰: 4 α ≤ 4*
cap: α(n) 長得極慢：到宇宙原子數量級都還不超過 4
```

union by rank 的保證來自：**rank 只有在兩個一樣 rank 的根合併時才加 1**。

所以 rank 是 $r$ 的根，它的樹至少有 $2^r$ 個點（兩棵各至少 $2^{r-1}$ 的樹合起來）。$n$ 個點，rank 最多 $\lfloor\lg n\rfloor$，高度也最多 $\lg n$。

?? 填空 | 1000 個元素的 Union-Find（只用 union by rank），rank 最大可能是多少？
== 9
!! rank $r$ 至少 $2^r$ 個點：$2^r\le1000$。
>> $2^9=512\le1000<1024$，最大 9。

先看影片：怎麼接，樹才不會長歪。

@影片 ds-unionfind 0-64.9

其他性質：
- 從任何點往根走，**rank 嚴格遞增**
- rank 剛好是 $r$ 的點最多 $n/2^r$ 個
- 加上路徑壓縮之後，rank 不再等於高度，只是高度的**上界**

?? 選擇 | 用了路徑壓縮之後，一個根的 rank 是 3。它的樹高度？
[ ] 一定是 3
[x] 最多 3，可能更矮
!! 路徑壓縮讓樹變矮，但 rank 不會被更新。
>> rank 只是上界。

兩個方法一起用：$m$ 次操作（$n$ 個元素）總共 $O(m\,\alpha(n))$。$\alpha$ 是 Ackermann 函數的反函數，**長得慢到不可思議**：只要 $n$ 小於宇宙中原子的數量（$10^{80}$），$\alpha(n)\le4$。

但考試要注意兩件事：
- 理論上 $\alpha(n)$ **不是** $O(1)$（它會無限變大，只是非常慢）
- 這是**攤銷**的界，單次 FIND 還是可能 $O(\lg n)$

?? 選擇 | 「用 union by rank＋路徑壓縮後，每一次 FIND 都是 $O(\alpha(n))$」對嗎？
[ ] 對
[x] 不對
!! 這個界是攤銷還是最壞？
>> 是 $m$ 次操作的總和 $O(m\alpha(n))$，平均下來每次 $O(\alpha(n))$；某一次 FIND 可能要爬 $\lg n$ 層。

再看影片：路徑壓縮、α(n) 有多小，還有考試陷阱。

@影片 ds-unionfind 65.0-121.7

?? 寫 | 在手寫板寫出：為什麼 rank 為 $r$ 的根，樹至少有 $2^r$ 個點？（用歸納法的想法）
== rank 0：自己一個點，$2^0=1$ ✓。
== rank 從 $r-1$ 變 $r$：只會發生在兩個 rank $r-1$ 的根合併時，兩棵各至少 $2^{r-1}$ 點，合起來至少 $2^r$ ✓。
!! rank 什麼時候會增加？
>> 所以 rank ≤ $\lg n$。

@例題 只用 union by rank、不用路徑壓縮，$n=16$。最壞情況下一次 FIND 要往上走幾步？怎樣的 UNION 順序會造成？
@寫 高度上界 | rank 最多 $\lg16=4$，高度最多 4，FIND 最多 4 步。
@寫 造出高度 4 的樹 | 兩兩合併：8 棵 rank 1 → 4 棵 rank 2 → 2 棵 rank 3 → 1 棵 rank 4（像二項樹）。
@步 結論 | 最深的點要走 4 步；這也是為什麼 union by rank 單獨就有 $O(\lg n)$。
@答 最多 4 步；用「一樣大的兩兩合併」造出來。

=== ds-unionfind#3

goal: 會用 Union-Find 動態維護連通元件、判斷加一條邊會不會形成環；知道 Kruskal 用它；知道它不能拆開
---
> [!先記住]
> 只要問題是「東西一直被合在一起，常常問兩個東西是不是連在一起」，就用 Union-Find。最常考的是 **Kruskal 找最小生成樹**。

```fig

```

**連通元件**：一張圖一條邊一條邊加進來，隨時問「$u,v$ 連通了嗎？」
- 一開始每個點各自一組
- 加邊 $(u,v)$：UNION$(u,v)$

[ ] 全部連通

這正是 **Kruskal 最小生成樹**演算法的核心：把邊照權重由小到大看，**不會形成環才加進來**（之後最小生成樹那章會詳細學為什麼這樣是對的）。

[ ] 不會形成環

>> 1–2–3 已經連通，再加 1–3 就有環 1–2–3–1。

**做不到的事**：Union-Find **不能有效地拆開**一組（刪邊）。合併很容易，拆開要重建。

?? 選擇 | 一張圖會一直加邊、也會刪邊，要隨時知道連通性。Union-Find 適合嗎？
[ ] 適合
[x] 不適合，它不支援拆開
!! UNION 的反操作是什麼？
>> Union-Find 只能合併，刪邊時沒辦法把一組拆成兩組。

?? 寫 | 在手寫板用 Union-Find 判斷：邊 (a,b)、(b,c)、(d,e)、(c,a)、(e,f) 依序加入，哪一條加入時會形成環？

- 根：至少 1 個鍵
- **所有葉子在同一層**
- 節點內的鍵由小到大，像 BST 一樣把孩子隔開

[ ] 讓樹比較平衡

@例題 $t=100$ 的 B 樹存 $n=10^6$ 個鍵。高度最多是多少？搜尋最多讀幾次硬碟（根已經在記憶體裡不算）？

B 樹刪除比插入麻煩：刪掉後節點可能太瘦（少於 $t-1$ 個鍵）。

CLRS 的原則（跟插入對稱）：**往下走之前，先確定要去的那個孩子至少有 $t$ 個鍵**。這樣刪掉一個也不會太瘦，只要走一趟。

**情況 1**：鍵在**葉子** → 直接刪。

?? 選擇 | 為什麼情況 1 可以直接刪？
[x] 走下來之前已經保證這個葉子至少有 $t$ 個鍵
[ ] 葉子的鍵數沒有下限
[ ] 刪完會自動合併
!! 想想上面的原則。
>> 刪完還有 $\ge t-1$ 個，合法。

**情況 2**：鍵 $k$ 在**內部節點**。看 $k$ 左右兩個孩子：
- (a) 左孩子 $\ge t$ 個鍵：用 $k$ 的**前驅**（左子樹最大的）取代 $k$，再去左邊刪前驅
- (b) 右孩子 $\ge t$ 個鍵：用**後繼**取代，再去右邊刪
- (c) 兩個都只有 $t-1$ 個：把 $k$ 和兩個孩子**合併**成一個（$2t-1$ 個鍵），再往下刪 $k$

?? 選擇 | $t=2$。內部節點的鍵 $k$，左右孩子都只有 1 個鍵。要怎麼做？
[ ] 用前驅取代
[x] 把左孩子、$k$、右孩子合併，再刪 $k$
[ ] 直接刪
!! $t-1=1$，兩邊都不夠胖。
>> 情況 2(c)：合併成 3 個鍵的節點。

**情況 3**：鍵不在這個節點，要往某個孩子走。那個孩子只有 $t-1$ 個鍵時先補胖：
- (a) 隔壁兄弟有 $\ge t$ 個 → **借**一個：爸爸的分隔鍵下來，兄弟的一個鍵上去（像旋轉）
- (b) 兄弟也只有 $t-1$ 個 → 跟兄弟**合併**（爸爸的分隔鍵也下來，夾在中間）

?? 排序 | 情況 3 中，要往下走的孩子只有 $t-1$ 個鍵，處理順序是？
- 看隔壁兄弟有沒有 $\ge t$ 個鍵
- 有：透過爸爸借一個鍵
- 沒有：和兄弟、爸爸的分隔鍵合併
- 往下走，繼續找要刪的鍵
>> 先借，借不到才合併。

**變矮**：根只有一個鍵，它的兩個孩子被合併了 → 根變空、刪掉，合併出來的節點變成新根。這是 B 樹**唯一變矮的方式**。

?? 寫 | 在手寫板：$t=2$，根 [20]，孩子 [10]、[30]。刪除 20，畫出每一步。
== 20 在內部節點，左右孩子都只有 1 個鍵（$=t-1$）→ 情況 2(c)：合併成 [10,20,30]
== 根變空，[10,20,30] 變新根；在葉子裡刪 20（情況 1）→ [10,30]
!! 先檢查兩個孩子的鍵數。
>> 樹從 2 層變 1 層。

@例題 $t=2$。根 [20]，左孩子 [5,10]，右孩子 [30]。刪除 30。
@寫 30 不在根，要往右孩子走；右孩子只有 1 個鍵（$t-1$） | 先補胖：左兄弟 [5,10] 有 2 個（$\ge t$），用情況 3(a) 借。
@寫 借鍵 | 爸爸的 20 下到右孩子 → [20,30]；兄弟最大的 10 上到爸爸 → 根 [10]；左孩子剩 [5]。
@步 往下刪 | 右孩子 [20,30] 是葉子，刪 30 → [20]。
@答 根 [10]，孩子 [5]、[20]。

=== ds-btree#3
title: B+ 樹：資料都放在葉子，葉子串起來
mins: 25
goal: 說得出 B+ 樹和 B 樹的差別；知道為什麼資料庫用 B+ 樹（範圍查詢、扇出大）；會估算 B+ 樹的層數
---
> [!先記住]
> **B+ 樹**：所有資料都放在葉子，內部節點只放「路標」；葉子從左到右串成一條。所以範圍查詢（找 30 到 50 之間的全部）特別快，資料庫和檔案系統都用它。

```fig
tree
[30]([10 20],[30 40 50])
---
array
row 葉子串起來: 10 -> 20 -> 30* -> 40* -> 50*
cap: 找 30～50：先從根找到 30 所在的葉子，再沿著葉子往右走
```

**B+ 樹**是 B 樹的變形，資料庫索引幾乎都用它：
- **所有資料都在葉子**；內部節點只放「指路用」的鍵
- **葉子由左到右串成鏈結串列**
- 每次搜尋都走到葉子（B 樹可能在中途就找到）

?? 選擇 | B+ 樹的資料（或指向資料的指標）放在哪裡？
[x] 只在葉子
[ ] 只在內部節點
[ ] 每個節點都有
!! 內部節點的鍵是做什麼用的？
>> 內部節點只負責指路。

為什麼比較好？
- **範圍查詢**快：找到第一個，沿著葉子的鏈往右讀就好，不用在樹裡上上下下
- 內部節點不放資料，一頁能放更多鍵 → **扇出**（孩子數）更大 → 樹更矮

?? 選擇 | 「找出所有 100 到 200 之間的資料」，B+ 樹比 B 樹快，主要是因為？
[x] 葉子串成鏈，找到起點後往右讀
[ ] B+ 樹的鍵比較少
[ ] B+ 樹不用讀硬碟
!! 找到 100 之後，下一個在哪？
>> B 樹要做中序走訪，在不同層之間跳。

?? 填空 | 一頁 4096 位元組，一個鍵 8 位元組、一個子節點指標 8 位元組。一個內部節點大約能有幾個孩子？
== 256
!! 每個孩子大約佔一個鍵加一個指標。
>> $4096/16=256$。

**陷阱**：「內部節點的鍵一定也出現在葉子」✗。插入時分隔鍵是從葉子**複製**上去的；但之後刪掉葉子裡的那個鍵，內部的分隔鍵可以不改（它還是能正確指路）。

?? 寫 | 在手寫板寫出：在 B 樹和 B+ 樹中搜尋一個「剛好在根」的鍵，各要走幾層？為什麼？
== B 樹：在根就找到，1 層。
== B+ 樹：根的鍵只是指路，資料在葉子，一定要走到最底層。
!! 資料放在哪裡？
>> 所以資料搜尋都走到葉層，拜訪層數固定；實際磁碟讀取仍受快取影響。

@例題 B+ 樹每個內部節點 100 個孩子，每個葉子放 100 筆資料。存 100 萬筆，有幾層？找一筆要讀幾次硬碟？
@寫 葉子數 | $10^6/100=10^4$ 個葉子。
@寫 往上數 | $10^4$ 個葉子需要 $10^4/100=100$ 個爸爸；100 個再需要 1 個根。
@步 層數 | 根、中間一層、葉子：3 層，讀 3 次（根常駐記憶體就是 2 次）。

=== ds-btree#4
title: Trie：用字母當路徑的樹
mins: 25
goal: 會畫 Trie；知道搜尋長度 $m$ 的字串是 $O(m)$、跟字串總數無關；知道它擅長前綴查詢、缺點是空間大；知道 Patricia 和後綴樹在做什麼
---
> [!先記住]
> Trie 把字串一個字母一個字母往下存，找長度 $m$ 的字串只要 $O(m)$，跟存了幾個字串無關。

```fig
tree
[根]([c]([a]([t*],[r*])),[d]([o]([g*])))
cap: Trie 存 cat、car、dog：共用開頭的字母共用路。藍色代表「這裡是一個字的結尾」
```

**Trie**（字典樹）：每條邊是一個字母，從根往下走的路徑拼出一個字串。字串結尾的節點做記號。

例：{to, tea, ten, in}
- 根 → t → o（to 結尾）
- 根 → t → e → a（tea）、e → n（ten）
- 根 → i → n（in）

?? 選擇 | 在 Trie 裡搜尋長度 $m$ 的字串，時間是？（字母表大小當常數）
[x] $O(m)$，跟存了幾個字串無關
[ ] $O(\lg n)$，$n$ 是字串個數
[ ] $O(n)$
!! 每個字母走一步。
>> 走 $m$ 步就到，不管 Trie 裡有一百個還是一百萬個字串。

?? 填空 | 上面 {to, tea, ten, in} 的 Trie，連根算共有幾個節點？
== 8
!! 共用的前綴只算一次：t 和 e 被共用。
>> 根、t、o、e、a、n（ten）、i、n（in）＝8。

**強項：前綴查詢**。「所有 te 開頭的字」：走到 t→e，下面整棵子樹就是答案。雜湊表做不到。

**缺點：空間**。每個節點可能要為每個字母留一個指標。

?? 寫 | 在手寫板畫出 {car, cat, cart, dog} 的 Trie，並標出哪些節點是字串結尾。
== 根 → c → a → r（car 結尾）→ t（cart 結尾）；a → t（cat 結尾）
== 根 → d → o → g（dog 結尾）
!! car 是 cart 的前綴：r 節點要做結尾記號，但它下面還有東西。
>> 結尾記號不一定在葉子。

**壓縮**：一長串只有一個孩子的節點，合併成一條邊（存一段字串）→ **Patricia**（radix tree）。

**後綴樹**：把一個長字串（長度 $n$）的**所有後綴**放進壓縮 Trie。$O(n)$ 建好之後，查「某個長度 $m$ 的字串有沒有出現」只要 $O(m)$。省空間版是**後綴陣列**：把所有後綴排序，查詢用二分搜尋 $O(m\lg n)$。

?? 選擇 | 「banana 裡有沒有 nan？」用後綴樹查，時間跟什麼有關？
[x] nan 的長度
[ ] banana 的長度
[ ] 兩個都有關
!! 子字串一定是某個後綴的前綴。
>> 從根沿著 n-a-n 走，$O(m)$。

@例題 要做「輸入框打字時，列出所有以目前文字開頭的單字」。比較用 Trie 和雜湊表。
@寫 Trie | 每打一個字，從目前節點往下走一步（$O(1)$）；這個節點下面的子樹就是所有候選。
@寫 雜湊表 | 只能查「整個字串在不在」，要列出前綴相同的，只能全部掃一遍 $O(n)$。
@步 結論 | 前綴問題選 Trie；只要精確查找、又在意空間，選雜湊表。
@答 Trie 適合；雜湊表做不到有效率的前綴查詢。

=== ds-btree#5
title: 跳躍串列：用丟硬幣代替平衡
mins: 25
goal: 知道跳躍串列的結構和搜尋方式；知道期望高度 $O(\lg n)$、期望空間 $O(n)$、操作期望 $O(\lg n)$；分得清期望和最壞情況
---
> [!先記住]
> 跳躍串列靠丟硬幣決定每個元素有幾層，上層當快速道路，期望 $O(\lg n)$ 搜尋，不用旋轉。

```fig
array
row 第 2 層: 1 _ _ _ 9* _
row 第 1 層: 1 _ 4 _ 9 _
row 第 0 層: 1 3 4 7 9 12
cap: 跳躍串列找 7：第 2 層 1 → 9 過頭，往下；第 1 層 1 → 4 → 9 過頭，往下；第 0 層 4 → 7 找到
```

排好序的鏈結串列，搜尋要 $O(n)$（不能跳）。**跳躍串列**：在上面多蓋幾層「快速道路」。

- 第 1 層：所有元素
- 每個元素**丟硬幣**，正面就再往上一層（機率 $p$，通常 $\frac12$），一直丟到反面
- 平均每往上一層，元素少一半

?? 填空 | $n=1024$，$p=\frac12$。期望有幾個元素出現在第 3 層（含）以上？
== 256
!! 到第 3 層要連續兩次正面。
>> $1024\times\frac14=256$。

**搜尋**：從最上層開始往右走；下一個比目標大就**往下一層**，繼續往右。

?? 寫 | 在手寫板：第 1 層 1,3,5,7,9,11；第 2 層 3,7,11；第 3 層 7。搜尋 9，寫出經過哪些點。
== 第 3 層：從 7 開始（下一個沒了）→ 下到第 2 層的 7
== 第 2 層：7 的下一個是 11 > 9 → 下到第 1 層的 7；往右 9 ✓
!! 往右會超過就往下。
>> 經過 7（第 3 層）→ 7（第 2 層）→ 7 → 9（第 1 層）。

期望表現（$p=\frac12$）：
- 高度 $O(\lg n)$
- 空間：每個元素平均出現 $1+\frac12+\frac14+\cdots=2$ 層 → $2n$，一般是 $\frac{n}{1-p}$
- 搜尋、插入、刪除：期望 $O(\lg n)$

?? 選擇 | 跳躍串列搜尋的**最壞**情況時間是？
[ ] $O(\lg n)$
[x] $O(n)$
[ ] $O(1)$
!! 如果每次丟硬幣都是反面呢？
>> 運氣極差時所有元素都只在第 1 層，退化成普通串列。$O(\lg n)$ 是**期望值**。

跟平衡樹比：平衡樹靠**旋轉**維持高度，跳躍串列靠**隨機**，程式簡單、容易做並行。

?? 選擇 | 跳躍串列和紅黑樹最大的不同是？
[x] 跳躍串列用隨機維持效率，不用旋轉
[ ] 跳躍串列最壞情況也是 $O(\lg n)$
[ ] 紅黑樹不能存排序好的資料
!! 誰需要旋轉？
>> 紅黑樹保證最壞 $O(\lg n)$；跳躍串列只保證期望。

@例題 $p=\frac14$ 的跳躍串列存 $n$ 個元素。期望總共有幾個節點（每層每個元素算一個）？和 $p=\frac12$ 比呢？
@寫 每個元素平均幾層 | $1+\frac14+\frac1{16}+\cdots=\frac1{1-1/4}=\frac43$
@寫 總數 | $\frac43n$
@步 比較 | $p=\frac12$ 是 $2n$。$p$ 小 → 省空間，但每層跳得比較遠、層數 $\log_{1/p}n$ 變少、每層要往右走比較多步。
@答 期望 $\frac43n$ 個節點，比 $p=\frac12$ 的 $2n$ 少。
