=== rc:os-process:1
新建 → 就緒 → 執行 → 結束，執行中可能去「等待」。
- 就緒 → 執行：被排程選中。
- 執行 → 就緒：被中斷、時間片用完。
- 執行 → 等待：要做 I/O 或等事件。
- 等待 → 就緒：I/O 完成。

一定要排程的：執行 → 等待、執行 → 結束。可搶先系統另外在執行 → 就緒、等待 → 就緒時也會排程。

=== rc:os-process:2
父行程拿到子行程的 PID，子行程拿到 0，失敗回 −1。
- 子行程繼承：記憶體內容（一份拷貝）、開啟的檔案描述元、工作目錄、環境變數、訊號處理方式。
- 不繼承：自己的 PID 和父 PID、還沒處理的訊號、檔案鎖、計時器；而且只複製呼叫 fork 的那一條執行緒。

=== rc:os-process:3
5 個（含原本的）。
- 原本的 P 做第 1 個 fork → 生出 A。P 拿到正數，繼續做第 2 個 fork → 生出 B；P 的 `&&` 為真，`||` 後面不做。
- A 拿到 0，`&&` 直接失敗，去做 `||` 後面的第 3 個 fork → 生出 C。
- B 拿到 0，`&&` 失敗，也去做第 3 個 fork → 生出 D。

P、A、B、C、D 共 5 個。

=== rc:os-process:4
- 共享：程式碼、全域變數、heap、開啟的檔案、訊號處理方式。
- 私有：執行緒 ID、PC、暫存器、堆疊。

三種模型：
- 多對一：切換快；但一條阻塞全部阻塞，也不能用多核。
- 一對一：真的平行；但每條都是核心執行緒，開銷大（Linux、Windows 用這個）。
- 多對多：彈性最好；實作複雜。

=== rc:os-process:5
- Zombie：子行程已經結束，但父行程還沒用 wait() 收它的結束狀態，PCB 還留著。
- Orphan：父行程先結束，子行程還在跑，會被 init（PID 1）收養。

=== rc:os-sched:1
| 演算法 | 優點 | 缺點 |
|---|---|---|
| FCFS | 簡單 | 護航效應，短工作被長工作卡住 |
| SJF | 非搶先中平均等待最短 | 要預知長度；長的會餓死 |
| SRTF | 所有演算法中平均等待最短 | 切換多；長的會餓死 |
| RR | 反應快、公平 | 平均周轉通常較長，時間片難選 |
| 優先權 | 彈性 | 低優先權會餓死（用 aging 解） |

=== rc:os-sched:2
$\tau_{n+1}=\alpha\,t_n+(1-\alpha)\,\tau_n$（t 是這次實際值，τ 是預測值）。
- α = 0：完全不看最近的實際值，預測永遠不變。
- α = 1：只看上一次的實際值。

常用 α = 1/2。

=== rc:os-sched:3
- 太大：退化成 FCFS。
- 太小：大部分時間都花在 context switch。

經驗法則：大約 80% 的 CPU burst 應該比時間片短。

=== rc:os-sched:4
- Rate-monotonic（週期越短優先權越高）：$\sum C_i/T_i\le n(2^{1/n}-1)$ 就一定排得了（n 很大時約 0.69）。這只是充分條件。
- EDF：$\sum C_i/T_i\le1$ 就排得了（截止期限 = 週期時是充要條件）。

=== rc:os-sched:5
- 新工作放進最高優先權的佇列。
- 用完整個時間片 → 降一級。
- 時間片內自己讓出 CPU（做 I/O）→ 留在原本那級。

防止飢餓：每隔一段時間把所有工作拉回最高級（priority boost），或等太久就升級（aging）。

=== rc:os-sync:1
1. 互斥：同一時間最多一個人在臨界區。
2. 前進：沒人在臨界區時，想進的人要能在有限時間內決定誰進，不想進的人不能擋路。
3. 有限等待：提出請求以後，別人插隊的次數有上限。

=== rc:os-sync:2
- 只用 turn（嚴格輪流）：違反「前進」。輪到 P0 但 P0 不想進，P1 想進也進不去。
- 只用 flag（先舉旗、再看對方）：兩人同時舉旗就互相等，永遠卡住，也違反「前進」。

=== rc:os-sync:3
```
flag[i] = true;
turn = j;
while (flag[j] && turn == j) ;   // 等
/* 臨界區 */
flag[i] = false;
```
現代處理器和編譯器會把沒有相依的讀寫重新排序（例如先讀 flag[j]、後寫 flag[i]），兩個人可能同時進去。需要記憶體屏障（memory barrier）。

=== rc:os-sync:4
生產者先 wait(mutex) 再 wait(empty)：緩衝區滿的時候，生產者拿著 mutex 在 wait(empty) 睡著；消費者要先 wait(mutex) 才能拿東西出來，也睡著 → 互相等，死結。

=== rc:os-sync:5
- Hoare：signal 之後立刻把控制權交給被叫醒的人，條件保證還成立。
- Mesa：signal 只是把對方放回就緒佇列，叫醒人的那一方繼續跑；等對方真正執行時，條件可能又被改掉了。所以醒來要重新檢查：用 `while`，不能用 `if`。

=== rc:os-sync:6
高優先權的 H 在等低優先權的 L 手上的鎖，這時中優先權的 M 一直搶走 L 的 CPU，結果 H 被 M 間接卡住。
解法：優先權繼承（L 拿著鎖的期間，暫時提升到 H 的優先權），或優先權上限協定。

=== rc:os-deadlock:1
互斥、持有並等待、不可搶奪、循環等待。四個同時成立才可能死結。

=== rc:os-deadlock:2
- 每種資源只有一個：圖上有環 ⇔ 死結。
- 每種資源有好幾個：有環只是必要條件，不一定死結（環外的行程可能釋放資源，把環打破）。

=== rc:os-deadlock:3
死結 ⊂ 不安全；安全狀態一定不會死結。不安全只是「有可能」死結，不一定真的會。

=== rc:os-deadlock:4
資料結構（n 個行程、m 種資源）：Available[m]、Max[n][m]、Allocation[n][m]、Need = Max − Allocation。
安全性檢查要 $O(m\times n^2)$。

=== rc:os-deadlock:5
至少 $n(k-1)+1$ 個。最壞的情況是每個人都拿到 k−1 個、都差一個；只要再多一個，至少有一個人能做完，把資源還回來。

=== rc:os-memory:1
編譯時（產生絕對位址的程式）、載入時（可重定位的程式）、執行時（需要 MMU 硬體）。只有在執行時才繫結，邏輯位址才會跟實體位址不一樣。

=== rc:os-memory:2
- First fit：找第一個夠大的洞，最快。
- Best fit：找最小、但夠大的洞，會留下很多很小的碎片。
- Worst fit：找最大的洞，通常最差。

模擬顯示 first fit 和 best fit 空間利用率差不多，first fit 比較快。
50% 規則：用 first fit 配置了 N 個區塊，大約還有 0.5N 個區塊大小的空間會因為外部碎片浪費掉（約 1/3 的記憶體不能用）。

=== rc:os-memory:3
單層頁表、TLB 命中率 α、TLB 查詢時間 ε、記憶體存取時間 m：
$$EAT=\alpha(\varepsilon+m)+(1-\alpha)(\varepsilon+2m)$$
沒命中時要多讀一次記憶體裡的頁表。

=== rc:os-memory:4
- 多層頁表：頁表太大、需要一大塊連續空間 → 分層，只配置用得到的部分。
- 雜湊頁表：位址空間很大（64 位元）時，用雜湊找到對應的頁表項。
- 反轉頁表：每個實體框只有一項，整個系統一張表，很省空間。缺點：要搜尋整張表才找得到（通常配雜湊），而且很難做共享記憶體。

=== rc:os-memory:5
分段：外部碎片（大小不一的洞）。分頁：內部碎片（最後一頁用不滿）。

=== rc:os-vm:1
1. 存取記憶體時發現頁表項是 invalid → trap 到作業系統。
2. 檢查位址合不合法，不合法就終止行程。
3. 找一個空框；沒有就做頁替換（被換掉的是髒頁要先寫回）。
4. 排程磁碟把頁讀進來，這段時間 CPU 先給別人用。
5. 讀完更新頁表，設成 valid。
6. 重新執行剛剛出錯的那道指令。

=== rc:os-vm:2
$EAT=(1-p)\times\text{記憶體時間}+p\times\text{page fault 時間}$。
例：記憶體 200 ns、page fault 8 ms，想讓變慢不超過 10%：$200+p\times8{,}000{,}000\le220$ → $p<2.5\times10^{-6}$，大約四十萬次存取才能有一次 fault。差太多倍了，所以缺頁率必須極低。

=== rc:os-vm:3
給更多框，FIFO 的 page fault 反而變多。例：參考串 1,2,3,4,1,2,5,1,2,3,4,5，3 個框 9 次、4 個框 10 次。
堆疊演算法（LRU、OPT）保證不會發生：n 個框記得的頁，一定是 n+1 個框記得的頁的子集合。

=== rc:os-vm:4
精確 LRU：
- 計數器：每頁記住上次使用的時間，替換時找最小的。
- 堆疊：用到就移到頂端，最底下的就是 LRU。

近似：
- Clock（second chance）：指針繞圈，reference bit 是 1 就清成 0、給第二次機會；是 0 就換掉。
- Enhanced second chance：看 (reference, modify) 兩位，優先換 (0,0)，再 (0,1)、(1,0)、(1,1)。

=== rc:os-vm:5
行程拿到的框少於它正在用的頁（工作集）→ 不停 page fault → CPU 使用率下降 → 作業系統以為很閒，又加行程進來 → 更糟。
- Working set：只有在所有行程工作集大小加起來 ≤ 總框數時才讓它們跑，不夠就先暫停一個行程。
- PFF：fault 率太高就多給框，太低就收回框。

=== rc:os-vm:6
C 語言的二維陣列是一列一列存的。假設一頁剛好放一列：
- 依列走訪：每換一列才 fault 一次，共「列數」次。
- 依行走訪：連續的兩個元素在不同頁，框不夠時幾乎每次存取都 fault，共「列數 × 行數」次。

=== rc:os-storage:1
存取時間 = 尋軌時間 + 旋轉延遲 + 傳輸時間。
7200 RPM：轉一圈 60/7200 秒 ≈ 8.33 ms，平均要等半圈 ≈ 4.17 ms。

=== rc:os-storage:2
- FCFS：公平，但讀寫頭跑來跑去。
- SSTF：先服務最近的，平均快，但兩端的請求可能餓死。
- SCAN：電梯，往一個方向掃到底再回頭。
- C-SCAN：只往一個方向服務，掃到底直接跳回起點，等待時間比較平均。
- LOOK / C-LOOK：同 SCAN / C-SCAN，但只走到最遠的請求就回頭。

會飢餓的是 SSTF。

=== rc:os-storage:3
| | 容量（n 顆） | 能壞幾顆 | 小寫入要做的事 |
|---|---|---|---|
| RAID 0 | n | 0 | 寫 1 次 |
| RAID 1 | n/2 | 每組鏡像 1 顆 | 寫 2 次 |
| RAID 5 | n − 1 | 1 | 讀 2、寫 2 |
| RAID 6 | n − 2 | 2 | 讀 3、寫 3 |
| RAID 1+0 | n/2 | 每組鏡像 1 顆 | 寫 2 次 |

=== rc:os-storage:4
- 連續配置：讀得快、能隨機存取；但有外部碎片，檔案不好變大。
- 鏈結配置：沒有外部碎片；但隨機存取要一路走過去，指標壞掉就斷了。FAT 把所有指標集中成一張表，可以放在記憶體裡加速。
- 索引配置：每個檔案一個索引塊，能隨機存取、沒有外部碎片；但索引塊本身佔空間。

=== rc:os-storage:5
區塊大小 B、指標大小 p，一塊能放 B/p 個指標：
$$\text{最大檔案}=\left(\text{直接指標數}+\frac Bp+\left(\frac Bp\right)^2+\left(\frac Bp\right)^3\right)\times B$$
例：B = 4 KB、p = 4 B → B/p = 1024。12 個直接 + 單、雙、三重間接，三重間接那項是 $1024^3\times4\text{KB}=4\text{TB}$，總共約 4 TB。

=== rc:os-storage:6
- Hard link：另一個目錄項指到同一個 inode（連結數 +1）。不能跨檔案系統，通常不能連目錄；刪掉原本的名字，檔案還在。
- Symbolic link：一個存著路徑的小檔案。可以跨檔案系統、可以連目錄；原檔刪掉就變成斷掉的連結。
